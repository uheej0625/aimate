# 기능 확장

확장 시 플랫폼의 외부 객체를 공통 서비스 안으로 전달하지 않는다. 새 의존성은 container에서 조립하고, 변경한 동작·계약·설정의 위키를 함께 갱신한다.

## 일반 도구 추가

`src/tools/definitions/`에 default export JS 모듈을 추가한다. 기존 정의처럼 name, description, AI SDK inputSchema, async execute를 작성하고 필요한 enabled·platforms·requires를 지정한다.

execute는 전달받은 context의 서비스만 사용한다. 플랫폼 기능은 해당 플랫폼에 한정하고, abortSignal을 느린 작업에 전달한다. 새 서비스가 필요하면 ToolExecutionContextFactory와 container에 연결한다. 이름 중복, 필터 조건, 정상·오류·취소 결과를 검증한다.

```javascript
import { jsonSchema } from "ai";

export default {
  name: "example_tool",
  description: "개발 예시 도구",
  inputSchema: jsonSchema({ type: "object", properties: {} }),
  platforms: ["cli"],
  requires: [],
  execute: async (_input, context) => ({ platform: context.platform }),
};
```

위 예시는 등록 계약 설명용이다. 실제 유용한 결과와 입력 제약은 기능에 맞춰 정의한다.

## 캐릭터와 프롬프트 추가

유효한 ID의 캐릭터 디렉터리에 identity·variables를 준비하고 필요하면 reference.png를 둔다. config의 character와 캐릭터별 Discord 토큰 이름을 맞춘다.

프롬프트 팩의 chat/sequence.js와 참조 파일을 준비하고 정확히 한 system step을 둔다. chat·image 팩 이름은 각각 설정한다. `test/fixtures/prompts/minimal/`이 공개된 최소 계약 예시다. 실제 팩의 문구와 캐릭터 원문은 위키에 복제하지 않는다.

## 플랫폼과 명령 추가

새 플랫폼은 NormalizedMessage·ChannelPort·MessageEvent를 구현하고 createContainer에 플랫폼 client를 제공한다. 채널 생성·등록은 유스케이스로 처리한다. send 반환값은 실제 전송 확인 후 정규화한 메시지여야 한다.

Discord 명령은 data와 execute를 export하고 createDiscordApplication에서 필요한 진입점을 주입한다. 명령 등록은 deploy 작업이며 실제 Discord에 쓰므로 기능 검증과 구분해서 실행한다.

## 변경 범위를 정하는 실제 예

새 일반 도구를 추가하는 경우 definitions의 한 파일과 도구 실행 검증으로 끝날 수 있다. 반면 ‘특정 메시지에 답장하기’는 도구만 추가해 끝나지 않는다. 모델이 지정할 대상 ID, 채널 안에서의 대상 조회, ChannelPort의 답장 기능과 플랫폼 결과, 저장·관찰 정책까지 연결해야 한다. 현재 보존한 reply/react 초안은 이 확장의 참고 자료이며 구현 명세는 아니다.

응답 대기 시간을 바꾸는 경우 bufferTimeout과 Buffer 동작을 확인한다. ‘말이 끝났는지 모델이 판단하게 하기’는 타이머 수치 변경이 아니라 새 판단 작업의 취소·오래된 결과 폐기·재평가 정책이 필요한 변경이다. JEV 아이디어 문서를 현재 구현과 구분한다.

## 새 의존성을 연결하는 순서

1. 어느 서비스가 책임을 가질지 정하고 필요한 입력·결과를 정의한다.
2. 생성자 또는 실행 context에 의존성을 주입한다.
3. container에서 실제 객체를 만들고 연결한다.
4. 플랫폼에는 필요한 애플리케이션 진입점만 노출한다.
5. 오류·취소·부분 성공의 사용자 행동을 검증하고 관련 위키를 갱신한다.

정적 singleton이나 플랫폼 client를 공통 모듈에서 직접 import하면 테스트에서 교체하기 어렵고 실행 환경별 상태가 섞일 수 있다. 기존 주입 경계를 사용하는 방향으로 변경한다.

## 근거와 검증 및 문서 갱신

구현: `src/tools/ToolRegistry.js`, `src/tools/ToolExecutionContextFactory.js`, `src/core/container.js`, `src/platforms/discord/handlers/commandHandler.js`.

관련 테스트: `test/tools/ToolRegistry.test.js`, `test/tools/ToolExecutionContextFactory.test.js`, `test/core/container.test.js`, `test/platforms/discord/createDiscordApplication.test.js`.

새 기능의 외부 행동을 검증하는 테스트를 추가하고 [테스트와 프롬프트 비교](테스트와%20프롬프트%20비교.md)의 절차를 사용한다. 사내용 개발 프로젝트이므로 호환 계층이나 데이터 마이그레이션을 추가하지 않는 AGENTS 원칙을 따른다.
