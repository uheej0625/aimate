# 테스트와 프롬프트 검증

자동 검증은 Node 내장 test runner를 사용한다. `npm test`는 cross-env로 NODE_ENV=test를 지정하고 `test/**/*.test.js`를 실행한다. 테스트 모드에서는 일반 설정 watcher와 development pretty 로깅을 억제한다.

## 검증 범위

| 대상 | 검증 위치와 핵심 시나리오 |
| --- | --- |
| 수신·저장 | `test/messages/`: 중복·편집·삭제, 관찰 정책과 snapshot |
| 세션·생성 | `test/chat/`: debounce, 순서·취소, 조건부 상태 전이 |
| 프롬프트 | `test/chat/context/`: sequence, 시간 표지·배치, 필수 파일 |
| AI·도구 | `test/ai/`, `test/tools/`: 모델 선택, native 도구, 이미지·abort |
| 플랫폼 | `test/platforms/`: 어댑터, Discord 삭제·기동, CLI TUI |
| 공통 흐름 | `test/integration/ChatPipeline.integration.test.js`: 파이프라인의 경합과 완료 |

```powershell
npm test
$env:NODE_ENV = 'test'
node --test test/chat/ConversationSession.test.js test/messages/MessageHandler.test.js
```

테스트 근거는 구현 의도를 확인하는 자료이며 실서비스의 네트워크 성공을 보장하지 않는다. 수정한 행동에 필요한 검증부터 실행한다. 문서만 변경할 때는 링크·경로·다이어그램과 설명의 정확성을 확인한다.

## 프롬프트 검증

`test/chat/context/`에서 컨텍스트 조립·sequence·시간 표지·필수 파일을, `test/chat/response/AIResponseParser.test.js`에서 응답 파싱을 검증한다. 자동 검증 통과가 실제 모델의 자연스러움·캐릭터·상황 대응을 보장하지는 않는다. 모델 입력과 응답에 포함된 비공개 원문은 위키에 복사하지 않는다.

## 테스트 파일을 고르는 기준

메서드 반환과 객체 간 호출 계약을 바꾸면 해당 단위 테스트를 먼저 확인한다. 저장과 취소 순서, cursor, 플랫폼 전송 결과가 함께 바뀌면 ChatPipeline 통합 테스트가 필요하다. 이 통합 테스트는 별도 임시 SQLite DB와 모델 대체 함수를 사용해 동작을 재현한다.

현재 핵심 통합 시나리오는 중복 봇 echo, 비주시 편집, 주시 중 삭제, 전송 도중 새 변화, 철회한 출력의 재등장 방지, 저장 재시도 시 중복 전송 방지다. 코드 줄마다 구현을 따라 쓰는 테스트보다 이 사용자 행동이 유지되는지 확인한다.

## 근거와 관련 문서

구현: `package.json`, `src/chat/context/`, `src/chat/response/AIResponseParser.js`.

테스트: `test/chat/response/AIResponseParser.test.js`, `test/chat/context/ContextAssembly.test.js`, `test/integration/ChatPipeline.integration.test.js`.
