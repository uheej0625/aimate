# AiMate 개발 로드맵

작성일: 2026-10-15 · 상태: 계획 문서

이 문서는 앞으로의 개발 목표와 순서를 정리한다. 마일스톤과 완료 조건은 계획이며, 현재 구현 완료를 의미하지 않는다. 현재 동작은 [전체 아키텍처](../구조/전체%20아키텍처.md)와 각 기능 문서를 참고한다.

## 목표와 기본 방향

개인·지인용 Discord를 중심으로, 여러 사람과 관계를 맺고 자기 생활을 이어가는 캐릭터를 만든다. 기억과 생활의 연속성을 먼저 완성하고 음성·시각적 교류로 확장한다.

- 혼자 집중적으로 개발하며, 기간보다 단계별 완료 조건으로 관리한다. 1~2주마다 작동하는 결과를 확인하고 실제 소요 기간은 단계 진입 시 산정한다.
- N:1은 **여러 사람과 캐릭터 하나가 같은 방에서 대화하는 구성**이다.
- 코드 생성 기능은 로드맵에서 제외한다.
- 부재 시 응답 정책, Decision 공급자, 통화·영상 구현 방식은 해당 단계에서 결정한다.
- 기존 플랫폼 분리와 대화 파이프라인을 활용한다. 전면 재작성은 하지 않는다.
- 프롬프트 개선·로그·테스트·코드 정리는 모든 단계에 포함한다.

## 마일스톤과 순서

| 단계 | 핵심 결과 | 주요 범위 | 완료 조건 |
| --- | --- | --- | --- |
| **M0. 개발·운영 기준선** | 문제를 재현하고 원인을 추적한다 | 기존 테스트 기준선, 생성·도구·전송 로그 연결, 프롬프트 평가 사례, DB 백업·복원, 필요한 코드 정리 | 문제 대화 하나를 끝까지 추적하고 변경 전후를 비교할 수 있다 |
| **M1. Content·확장 계약의 초안** | 콘텐츠와 확장의 경계를 명확히 한다 | character·prompt 규격 문서화, 버전·검증·호환성, 플러그인 등록·설정·수명주기와 확장 지점 초안 | 기존 콘텐츠가 검증을 통과하고, 예제 플러그인을 코어 수정 없이 등록·해제할 수 있다 |
| **M2. Fact·Episode 메모리** | 사람과 경험을 기억한다 | 추출·저장·검색·주입, 출처·시점·공개 범위, 정정·삭제, 단기 대화 요약 | 지난 사실과 사건을 회상하고, 틀린 기억을 고치며 사람별 기억을 구분한다 |
| **M3. Decision 기반 대화 참여** | 답할 때와 기다릴 때를 구분한다 | 응답·대기·무응답 판단, 기존 동작과 비교 기록, 오래된 판단 폐기, 실패 시 대체 동작 | 직접 질문을 놓치지 않으면서 불필요한 답변과 생성 취소를 줄인다 |
| **M4. N:1 채팅 완성** | 여러 사람과 자연스럽게 대화한다 | 발언·응답 대상 구분, 동시 발언, 사람별 관계, 개인·공유 기억 경계 | 세 사람 이상과 대화해도 발언·취향의 주인을 혼동하지 않고 적절히 참여한다 |
| **M5. 캐릭터의 생활** | 대화 밖에서도 시간이 흐른다 | 일정·장소·활동·가용 상태, 생활 사건, 재시작 복구, 대화·사진·상태 표시 연동 | 학교·이동·귀가가 이어지고 말과 사진이 같은 생활 상태를 반영한다 |
| **M6. Humanize·능동적 관계** | 먼저 연락하고 약속을 이어간다 | 맥락별 응답 타이밍, 선제 연락, 약속 후속 대화, 기분·관계의 연속성 | 이전 교류와 생활 사건이 다음 행동에 영향을 주고 연락 빈도를 제어할 수 있다 |
| **M7. Content·플러그인 규격 v1** | 확장을 안정적으로 제작·교체한다 | 실제 기능으로 계약 검증, 호환성·업그레이드 정책, 예제·개발 문서, 오류 처리 | 기존 팩과 플러그인의 호환 여부를 판별하고 업그레이드할 수 있다 |
| **M8. 음성 통화** | 같은 캐릭터와 음성으로 대화한다 | 1:1 음성 입출력, 끼어들기·중단, 연결 복구, 통화 기억 | 통화를 끊고 다시 연결할 수 있으며 이후 채팅에서도 내용을 기억한다 |
| **M9. 화면공유·화상통화** | 함께 보고 반응한다 | 정지 화면 이해 → 연속 화면·음성 결합, 사용자 영상 이해, 캐릭터 영상 표현 검증 | 공유 화면의 변화에 반응하며 선택한 형태의 화상 경험을 제공한다 |

M1은 사용할 수 있는 초안이고, M7은 실제 확장 경험을 반영한 안정 버전이다. 플러그인 사용을 M7까지 미루지는 않는다. 메모리·참여 판단·생활 기능을 개발하면서 확장 계약을 검증한다.

## 주요 설계 방향

### Content 규격

- 캐릭터 정의, 프롬프트 팩, 실행 설정, 런타임 상태의 책임을 구분한다.
- 필수 파일·필드, 템플릿 변수, 프롬프트 입출력 계약, 버전과 검증 오류를 문서화한다.
- 메모리와 생활 상태는 런타임 데이터로 공급하고, 콘텐츠에는 이를 표현하는 설정과 템플릿을 둔다.
- 기존 콘텐츠의 이전 경로와 검증 도구를 함께 제공한다.
- 현재 프롬프트의 `sequence.js`처럼 실행 코드가 포함되는 부분은 콘텐츠와 플러그인의 경계를 정할 때 명시적으로 다룬다.

### 플러그인

- 도구뿐 아니라 컨텍스트 공급, 기억 처리, 대화 참여 판단, 생활 사건까지 확장 대상으로 삼는다.
- M1에서는 등록·설정·시작·종료 계약과 도구·컨텍스트 확장부터 구현한다. 나머지 계약은 해당 기능 개발 중 구체화한다.
- 실행 순서, 취소 신호, 오류 처리, 사용 가능한 서비스 범위를 명시한다.
- 느린 보조 작업을 응답 경로에 그대로 연결하지 않는다.
- 초기 대상은 사용자가 신뢰하는 로컬 플러그인이다. 공개 마켓과 임의 코드의 안전한 실행 환경은 별도 후속 과제로 둔다.
- 코어는 생성·전송·취소의 일관성을 유지하고, 플러그인은 정해진 계약을 통해 참여한다.

### Fact·Episode 메모리

- Fact는 취향·인물 정보·현재 상태처럼 이후 대화에서 다시 사용할 사실을 다룬다.
- Episode는 언제 누구와 무슨 일이 있었고 관계상 어떤 의미였는지를 담는다.
- 기억에 인물·캐릭터·출처·시간·공개 범위를 연결한다. 사실 변경, 중복, 추측과 확정 정보의 구분을 다룬다.
- 기억 확인·정정·삭제 수단을 제공한다. 개인 대화에서 얻은 기억을 단체방에 무조건 노출하지 않는다.
- 장기 기억과 현재 대화의 짧은 요약을 구분하고, 컨텍스트 예산 안에서 필요한 기억을 선택한다.
- 추출 작업 때문에 답장이 늦어지지 않도록 대화 생성과 보조 작업을 분리한다.

### Decision API와 N:1 대화

- 공급자에 독립적인 대화 참여 판단 인터페이스를 둔다.
- 결과는 우선 `응답 / 대기 / 무응답`으로 구분하고, 진행 중인 생성의 취소 여부는 별도 판단으로 다룬다.
- 기존 동작을 유지하며 판단만 기록한 뒤, 평가 결과를 보고 점진적으로 적용한다.
- 대기 후 재평가, 오래된 판단 폐기, 타임아웃·실패 시 대체 동작을 포함한다.
- 무응답을 메시지 삭제나 기억 대상 제외와 동일하게 취급하지 않는다.
- 여러 사람의 연속 발언, 직접 질문·멘션·답장, 사용자끼리의 대화를 구분한다. 관련 없는 새 발언 때문에 생성이 계속 취소되는 상황을 다룬다.
- M5 이후에는 생활 상태도 판단 입력으로 추가한다. 공급자·모델·세부 임계값은 M3 진입 시 결정한다.

기존 [JEV 응답 게이트 아이디어](../archive/jev-response-gate-idea.md)는 참고 자료다. JEV 채택은 확정하지 않았으며, 해당 문서의 외부 API·SDK 조건은 구현 전에 다시 검증한다.

### 생활과 Humanize

- 캐릭터 시간대에 따라 일정·장소·활동·가용 상태를 관리하고 재시작 후 복구한다.
- 대화·이미지 도구·Discord 상태는 같은 생활 상태를 조회한다. 생활에서 발생한 사건은 Episode와 연결한다.
- 매 순간 모델을 호출하지 않고 일정 전환과 의미 있는 사건을 중심으로 처리한다.
- 실제 부재, 응답 지연, 즉시 호출 수단의 정책은 M5 진입 시 결정한다.
- Humanize는 타이핑 지연에서 읽음·응답·침묵·화제 전환과 맥락별 타이밍으로 확장한다.
- 생활 사건과 이전 약속을 계기로 먼저 연락하고, 선제 연락 빈도와 조용한 시간을 사용자가 제어할 수 있게 한다.
- 기분과 관계 변화가 말투와 행동에 이어지되 근거 없이 급변하지 않게 한다.

### 음성·시각 확장

- 음성은 먼저 1:1 통화로 완성하고 다인 음성은 후속으로 둔다.
- 음성과 시각 입력도 기존 기억·생활·관계 맥락을 공유한다.
- 끼어들기, 응답 중단, 연결 해제와 재접속을 핵심 검증 대상으로 삼는다.
- 화면공유는 정지 화면 이해부터 검증한 뒤 연속 화면과 음성을 결합한다.
- 화상통화는 사용자 영상을 이해하는 기능과 캐릭터 영상을 보여주는 기능을 나눠 설계한다.
- 단계 진입 시 플랫폼의 공식 지원 범위와 지연·비용을 검증한 후 구현 방식을 선택한다. 별도 앱 개발이나 영상 생성 방식은 미리 확정하지 않는다.

## 병행 작업과 검증 기준

매 단계에서 사용자 경험과 내부 품질을 함께 확인한다.

| 분야 | 핵심 검증 |
| --- | --- |
| 안정성 | 중복 수신, 생성 중 새 입력, 부분 전송 후 실패, 재시작과 DB 복원 |
| Content·플러그인 | 필수 항목 누락, 버전 비호환, 중복 등록, 실행 순서, 오류·취소·종료 처리 |
| 메모리 | 사실 변경, 잘못된 추출, 근거 없는 회상, 사람 혼동, 개인 기억 노출, 정정·삭제 반영 |
| Decision·N:1 | 직접 질문 누락, 불필요한 끼어들기, 무한 대기, 늦게 도착한 판단, 연속 발언 중 생성 취소 |
| 생활·Humanize | 시간대·날짜 전환, 재시작, 말과 사진의 모순, 선제 연락 중복·과다 |
| 음성·시각 | 끼어들기, 연결 해제, 오래된 화면에 대한 반응, 통화 후 기억 연결 |

로그는 채널·캐릭터·생성 ID를 기준으로 연결하고 프롬프트·콘텐츠·플러그인 버전, 사용된 기억과 생활 상태, 참여 판단 결과를 추적한다. 기능별 지연·사용량·실패 단계도 기록하며 보관·삭제 범위를 정한다.

프롬프트 평가는 [기존 비교 스크립트](테스트와%20프롬프트%20비교.md)를 확장해 같은 사례로 반복한다. 캐릭터 정체성, 기억, 생활 상태, 대화 참여 정책을 구분하고 자연스러움과 일관성을 검토한다.

코드 정리는 해당 기능의 변경을 방해하거나 실패 원인이 되는 구간을 우선한다. 보조 작업의 재시도·중복 방지·재시작 복구를 단계적으로 갖춘다. 초기에는 기존 Node.js·Prisma·SQLite 구조와 플랫폼 어댑터 경계를 유지하고, 서비스 분리나 DB 교체는 측정된 필요가 생겼을 때 검토한다.

## 다음 착수 범위

M0 기준선 확보와 M1 규격 초안 작성부터 진행한다. 이후 M2에서 **사실 하나를 기억하고 회상·정정하기**를 먼저 완성하며 확장 계약이 실제로 적합한지 검증한다.
