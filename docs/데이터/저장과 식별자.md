# 저장과 식별자

플랫폼 ID와 내부 DB ID를 구분한다. Discord의 메시지 ID나 CLI UUID를 내부 Message.id로 사용하지 않는다.

| 식별자 | 의미와 제약 |
| --- | --- |
| `platform + platformId` | 계정·서버·채널·메시지의 플랫폼별 고유 키 |
| `Message.id` | 전역 autoincrement Int. 채널별 순번이 아님 |
| `Event.id` | 전역 autoincrement Int. 경험의 처리·정렬 기준 |
| `Generation.id` | 전역 autoincrement Int. 생성과 출력·이미지 연결 |
| `characterId + channelId` | ConversationState 복합 기본 키 |
| `turnId` | 메모리 작업 소유권 Symbol. 저장하지 않음 |
| 이미지 ID | 8자리 hex 파일 참조. Generation.id와 다름 |

채널별 `channelMessageNo`는 현재 스키마에 없다. [보존한 설계 초안](../v0.2.0/channelMessageNo와%20reply-react%20도구.md)은 아직 구현 계약이 아니다.

## 저장 책임과 원자성

MessageService가 관련 계정·채널을 준비하고 MessageRepository 트랜잭션 안에서 최신 상태와 Event를 기록한다. Repository의 직접 쓰기를 추가할 때에는 관찰 정책을 우회하지 않는지 확인한다.

Generation 입력에는 렌더링한 사용자 입력의 `{id, content}` 목록과 `eventSnapshot`을 JSON으로 저장한다. 입력 저장과 관련 Message.generationId 연결은 같은 트랜잭션이다. 이 연결은 이후 생성에서 바뀔 수 있으므로 고정 입력의 근거는 Generation.input이다.

Event snapshot에는 조회 cursor 범위와 사건 목록·입력 사건 ID를 저장한다. 일반 HISTORY 읽기는 pending 입력으로 취급하지 않는다. 정상 완료에서만 ConversationState cursor를 `throughInclusive`까지 전진시키며 작은 값으로 되돌리지 않는다.

`discardedAt`은 재생성으로 철회한 경험을 컨텍스트에서 제외하는 표식이다. 기존 COMPLETED Generation을 취소 상태로 바꾸는 것과 다르다. 삭제된 Message의 본문과 Event snapshot이 DB에 남을 수 있으므로 soft delete를 데이터 완전 삭제로 해석하지 않는다.

## Repository별 수정 지점

| Repository | 핵심 작업 | 변경할 때 확인할 정책 |
| --- | --- | --- |
| MessageRepository | 플랫폼 ID 조회, 현재 상태 갱신, soft delete, tombstone | 중복 수신과 늦은 편집·삭제의 순서 |
| EventRepository | 마지막 관찰 조회, 사건 생성, snapshot 구성 | 캐릭터별 경험, 처리 cursor와 철회 필터 |
| GenerationRepository | 생성, 입력 연결, 조건부 상태 갱신, completeChat | 취소 결과의 되돌림 차단과 cursor 원자성 |
| ChannelRepository | upsert, 플랫폼 ID/내부 ID 조회, 플랫폼별 목록 | 플랫폼 ID와 내부 ID를 섞지 않기 |
| User·PlatformAccount·Server Repository | 사용자·계정·서버 준비 | 고유 키와 계정 연결의 범위 |

MessageRepository의 활성 조회는 deletedAt이 없는 메시지를 대상으로 한다. 직접 Prisma 조회를 추가할 때 같은 필터가 자동 적용되는 것은 아니다. 새 조회가 삭제된 메시지나 철회 출력을 노출하는지 확인한다.

## 같은 트랜잭션이어야 하는 경계

메시지 변경만 성공하고 EDIT 기록이 실패하면 최신 상태와 관찰 경험이 어긋난다. MessageService의 변경 트랜잭션에서는 두 쓰기가 함께 성공하거나 함께 롤백한다. 이 경계는 통합 테스트의 failed observation write 사례로 확인한다.

completeChat은 GENERATED 확인, COMPLETED·sentAt 기록, ConversationState upsert와 cursor 증가를 묶는다. cursor가 이미 더 크면 작은 snapshot 범위로 되돌리지 않는다. 모델 호출이나 플랫폼 전송까지 이 DB 트랜잭션에 포함하지 않는다.

Generation.input은 JSON 문자열이라 DB가 그 내부 구조를 검증하지 않는다. input 형태를 바꾸면 기록 코드, HistoryService 재생성, GetGenerationInfo 표시를 함께 확인해야 한다.
