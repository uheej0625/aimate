# 메시지 사건과 대화 주시

구현 기준: 2026-09-20. 단일 Node.js 프로세스, SQLite, 캐릭터별 애플리케이션 컨테이너를 전제로 한다.

## 목적

현재 메시지의 내용과 AI가 경험한 내용을 구분한다. 사용자 발언을 받은 뒤 수정되거나 삭제되어도, 주시 중 목격한 원문과 변화는 다음 생성 입력에 남는다.

```text
READ   "하 정말"
EDIT   같은 메시지의 현재 내용 "아 그게"
→ 모델은 원문과 수정 사실을 함께 받는다.
```

특정 반응 문구를 강제하지 않는다. 수정 이유나 삭제 실행자를 추측하지 않는다.

## 데이터의 역할

| 대상 | 의미 |
| --- | --- |
| 입력 `MessageEvent` | 플랫폼의 CREATE / UPDATE / DELETE 통지. 영속 관찰 기록과 별개다. |
| `Message` | 플랫폼 메시지의 최신 내용, 편집 시각, 삭제 여부. 메시지당 한 행이다. |
| `Event` | 실제로 목격한 발언·변화 또는 확인된 자기 출력. 기존 스냅샷은 수정하지 않는다. |
| `ConversationState` | 캐릭터·채널별 마지막 정상 처리 사건 ID. 정상 완료와 같은 트랜잭션에서 전진한다. |
| `Generation.input` | 고정 사건 범위, 사건 스냅샷, 실제 반응 대상 ID와 렌더링된 입력. |
| `ConversationSession` | 인메모리 주시 상태, 현재 작업 토큰, 채널별 짧은 작업의 순서. |

Event의 종류는 READ, EDIT, DELETE, SENT다. READ의 source는 LIVE 또는 HISTORY다. HISTORY는 과거 메시지의 현재 상태를 지금 읽은 것이며, 새 사용자 발언이나 목격한 편집이 아니다.

모든 수신 이벤트를 별도로 저장하거나 observed 불리언으로 분류하지 않는다. 저장된 Event 자체가 경험이다. DB 전체 복원을 위한 이벤트 소싱은 사용하지 않는다.

## 주시 범위

- 유효한 새 사용자 발언을 받아들이면 즉시 주시한다. 모델 호출까지 기다리지 않는다.
- 버퍼 대기·생성·전송 중에는 계속 주시한다.
- 정상 응답은 마지막 조각의 실제 전송 확인 시각부터 10분간 주시한다. DB 저장 지연으로 기간을 늘리지 않는다.
- 후속 작업 없이 실패·취소로 끝나면 종료 시각부터 10분간 주시한다.
- 정확히 10분이 된 시점부터 비주시다. 사건 수신 시각을 기준으로 판정한다.
- 목격한 사용자 변화는 기존 작업을 교체하고 다시 debounce한다. 새 작업 종료부터 유예를 계산한다.
- 중복·무변경 이벤트, 봇 메시지만의 삭제는 응답을 예약하거나 주시 시간을 연장하지 않는다.
- 이전 작업의 finally는 새 작업의 상태를 바꾸지 못한다.
- 재시작하면 비주시다. Event와 처리 위치는 DB에 남는다.

시간 비교에는 주입 가능한 단조 시계를 사용한다. 별도의 주시 만료 타이머는 없다.

## 처리 흐름

```text
Discord / CLI
  → MessageEvent 어댑터
  → 채널별 수신 순서 보존
  → 현재 상태와 주시 여부 판정
  → Message 갱신 + 필요한 Event를 같은 트랜잭션에 저장
  → 반응 대상이면 기존 생성 취소 + 새 작업 토큰 + debounce
  → 사건 범위 고정 + Generation 입력 저장
  → 모델 생성
  → 현재 작업 확인 + 조각 전송 + Message / SENT 저장
  → 정상 완료 + 처리 위치 전진
  → 전송 종료 후 10분 주시
```

어댑터는 순수 메시지 데이터와 최소 채널 포트를 제공한다. 부분 메시지의 fetch는 지연 함수로 전달해, 조회 완료 순서 때문에 사건 순서가 바뀌지 않게 한다.

채널 큐는 상태 전환과 짧은 DB 작업을 직렬화한다. 모델 호출과 전송의 네트워크 대기는 큐 밖에서 수행하므로 그동안 도착한 수정·삭제를 처리할 수 있다. 전송 시작과 완료 채택은 같은 큐에서 현재 작업 토큰을 확인한다. 이미 시작된 플랫폼 전송은 되돌리지 않으며, 확인된 조각은 남기고 다음 조각부터 중단한다.

## 사건별 동작

| 수신 내용 | 현재 Message | 관찰 Event | 응답 |
| --- | --- | --- | --- |
| 새 사용자 발언 | 생성 | READ / LIVE | 예약 |
| 주시 중 수정 | 최신 내용 갱신 | EDIT | 교체·예약 |
| 비주시 중 수정 | 최신 내용·편집 표시 갱신 | 없음 | 없음 |
| 주시 중 알려진 메시지 삭제 | soft delete | DELETE | 사용자 메시지가 포함되면 예약 |
| 비주시 중 삭제 | soft delete | 없음 | 없음 |
| 확인되지 않은 ID 삭제 | 내용·작성자 없는 삭제 행 | 없음 | 없음 |
| 확인된 봇 출력 | 생성 | SENT | 없음 |
| 과거 내역의 현재 상태를 읽음 | 변경 없음 | READ / HISTORY, 같은 스냅샷은 중복 기록하지 않음 | 이것만으로 예약하지 않음 |

처음 보는 완전한 수정 메시지도 현재 상태를 저장할 수 있다. 이전 내용은 미상이다. 빈 문자열로 바꾸는 수정은 유효하다. 플랫폼 편집 시각이 이전인 갱신은 거부한다. 같은 내용·버전의 반복 통지는 기록하지 않지만 A→B→A는 두 변화다.

삭제 행은 늦은 CREATE/UPDATE가 메시지를 부활시키지 못하게 한다. 모르는 삭제 ID도 같은 원칙으로 보관하되, 그것을 AI가 목격한 원문으로 만들지 않는다.

대량 삭제는 같은 트랜잭션에서 메시지별 Event를 만들고 batchId를 공유한다. 응답 예약은 배치당 한 번이다. 배치 안의 순서를 실제 삭제 순서라고 해석하지 않는다.

## 목격한 내용과 현재 내용

A를 본 뒤 비주시 중 B로 바뀌고, 다시 주시 중 삭제되면 DELETE에 보존할 원문은 A다. DB의 B를 복사해 보지 못한 내용을 노출하지 않는다.

나중에 살아 있는 B를 실제 컨텍스트에 읽을 때는 READ / HISTORY로 남긴다. Discord의 `editedAt`은 편집 표시·버전으로 보존하고, 모델에는 “수정됨 표시 있음, 편집 시점은 목격하지 않음”으로 전달한다.

편집·삭제 표기와 인용한 본문은 사용자 역할의 데이터다. 시스템 지시로 승격하지 않는다. 봇 출력 조각은 assistant 역할로, 사건 순서를 유지해 전달한다.

## 완료, 실패, 재생성

미응답 판정은 마지막 봇 메시지가 아니라 처리 위치 이후의 사용자 READ / LIVE, EDIT, DELETE로 한다. 부분 전송만으로 입력을 완료 처리하지 않는다. 과거 참고 사건은 설정된 개수로 제한하지만 미처리 사건은 조용히 잘라내지 않는다. 모델의 입력 한도를 넘겨 호출이 실패하면 처리 위치는 유지한다.

완료와 커서 전진은 같은 DB 트랜잭션에서 수행한다. 취소·실패 시 커서는 유지하고 재시도는 같은 경험을 다시 읽는다. 생성 중 새 사건이 도착하면 이전 입력 범위에 끼워 넣지 않고 작업을 교체한다.

재생성은 원본의 입력 사건 ID를 재사용하며 커서를 뒤로 옮기지 않는다. 교체된 출력의 Generation은 discardedAt으로 표시해 이후 컨텍스트에서 제외한다. 원문 Event는 보존한다. 삭제 대상은 원본 Generation의 봇 출력만이며, 플랫폼에서 실제로 삭제가 확인된 ID만 현재 Message에 반영한다.

삭제 명령과 플랫폼 삭제 통지는 같은 MessageHandler를 거쳐 중복 변경·관찰을 막는다. 확인된 출력의 DB 저장 실패는 같은 플랫폼 메시지 ID로 한 번 재시도하며 메시지를 다시 전송하지 않는다.

## 검증과 한계

집중 테스트는 가짜 시계로 10분 경계, 이전 작업 종료, 부분 조회 순서를 확인한다. 실제 임시 SQLite 통합 테스트는 관찰 입력, 비주시 변경, 생성·전송 중 취소, 원문 보존, 완료 위치와 반복 재생성을 검증한다. 전체 회귀 검증은 `npm test`다.

주시 상태와 debounce 예약은 영속 큐가 아니다. 프로세스 종료 후 예약 자동 복구는 보장하지 않는다. 플랫폼이 전달하지 않은 변화, fetch 전에 사라진 중간 버전, 알 수 없는 원문은 재구성하지 않는다. 실제 Discord 전송 및 모델의 캐릭터 반응 품질은 별도 운영 확인 대상이다.
