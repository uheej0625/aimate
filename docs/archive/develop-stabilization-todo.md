## P1 — Event 전환 마무리

### 기억 추출을 Event 스냅샷 기준으로 변경

- [ ] 첫 Message 행이 아니라 고정된 `Generation.input.eventSnapshot`에서 화자와 근거 사건을 찾는다.
- [ ] 첫 메시지가 삭제되어도 뒤의 유효한 입력은 처리한다.
- [ ] N:1 입력에서는 추출한 기억을 실제 발화자에게 귀속한다.
- [ ] 수정·삭제로 철회된 사실을 추가 기억으로 남기지 않는 최소 정책을 정한다.

완료 조건: 여러 사용자의 발언이 한 Generation에 포함돼도 기억이 다른 사용자에게 저장되지 않는다.

### 모델 입력에 화자와 시간 보존

- [ ] Event를 모델 메시지로 바꿀 때 작성자 식별 정보와 발언 시각을 전달한다.
- [ ] DM에서는 불필요한 표기를 줄이고, N:1에서는 같은 역할의 사용자를 구분할 수 있게 한다.
- [ ] READ, EDIT, DELETE, SENT의 관찰 순서가 유지되는지 테스트한다.

완료 조건: 서로 다른 사람이나 시각의 동일한 본문이 모델 입력에서 동일한 사건으로 축약되지 않는다.

### 미처리 입력의 크기 초과 복구

- [ ] Event 원본 보존과 모델 입력 예산을 분리한다.
- [ ] 미처리 사건이 입력 한도를 넘었을 때 사용할 요약 또는 구간 처리 정책을 정한다.
- [ ] 실패 후 새 사건이 추가돼도 영구적으로 같은 입력 크기 오류를 반복하지 않게 한다.
- [ ] 처리되지 않은 사건을 조용히 버리거나 커서를 앞당기지 않는 테스트를 추가한다.

완료 조건: 장기간 실패하거나 메시지가 몰린 채널도 원문 추적성을 유지하며 다시 응답할 수 있다.

### 사용자 첨부 입력 지원 범위 결정

- [ ] Discord 첨부 파일 중 모델에 전달할 종류와 크기 제한을 정한다.
- [ ] `NormalizedMessage`와 Event 스냅샷에 필요한 첨부 메타데이터를 보존한다.
- [ ] 이미지가 포함된 생성·수정·삭제 사건을 테스트한다.

완료 조건: 사용자가 보낸 지원 대상 이미지를 캐릭터가 실제 대화 맥락으로 볼 수 있다.

## P2 — 대화 품질 개선

### 무응답을 정상 결과로 표현

- [ ] “답장이 필요 없음”을 실패나 빈 출력과 구분하는 Generation 결과를 설계한다.
- [ ] 사소한 수정, 삭제, 대화 종료 신호에서 항상 2~4개 메시지를 보내지 않도록 한다.
- [ ] 무응답으로 처리한 사건의 커서 전진과 후속 입력 결합 규칙을 테스트한다.

완료 조건: 캐릭터가 응답하지 않기로 한 사건이 오류 안내를 만들거나 영원히 미처리로 남지 않는다.

### 오류 응답을 캐릭터 경험에 맞추기

- [ ] 고정된 어시스턴트식 오류 문구를 운영 로그와 사용자 표시 정책으로 분리한다.
- [ ] 캐릭터가 보내는 오류 표현이 필요하면 짧고 설정 가능한 대화 문구로 제한한다.
- [ ] 실패 안내 자체가 원래 사용자 입력을 처리 완료로 만들지 않는 기존 계약을 유지한다.

완료 조건: 장애 상황에서도 캐릭터 경험을 크게 깨뜨리지 않으며 원래 요청은 다음 정상 생성에 남는다.

### 실제 대화 로그로 버퍼 정책 평가

- [ ] 고정 5초 버퍼의 응답 지연, 추가 메시지 합류율, 생성 중 취소율을 기록한다.
- [ ] “너무 빨리 답함”, “너무 늦게 답함”, “답하지 않아도 됨” 사례를 별도로 수집한다.
- [ ] 데이터가 쌓인 뒤에만 `ResponseGate` 또는 가변 대기 시간을 실험한다.

완료 조건: 고정 버퍼를 바꾸는 결정에 실제 대화 사례와 측정값이 있다.

## 당분간 유지할 결정

- `Message`는 플랫폼의 최신 상태, `Event`는 캐릭터가 목격한 경험으로 유지한다.
- 핵심 응답 흐름은 명시적 호출로 유지하고 EventBus는 기억 추출 같은 부가 작업에만 사용한다.
- 작업 토큰, Abort, Generation 상태 검증은 서로 다른 실패 경계를 막으므로 합치지 않는다.
- cron과 완전한 이벤트 소싱은 현재 범위에 다시 넣지 않는다.
- Generation은 단순 삭제 가능한 로그가 아니라 재생성, 전송 상태, 처리 위치의 근거 데이터로 취급한다.
