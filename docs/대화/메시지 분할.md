# 메시지 분할

Discord의 2000자 전송 제한에 맞춰 긴 응답을 여러 메시지로 나눈다. `MessageSender.send`가 `MessageSplitter`를 호출하며, 타이핑 표시·지연을 담당하는 [Humanize](Humanize.md)의 활성 여부와 관계없이 분할한다. CLI도 같은 전송 정책을 사용한다.

## 파싱과 전송 순서

1. `AIResponseParser`가 `## messages`와 `[BREAK]`를 해석해 모델이 지정한 말풍선을 구분한다.
2. `GeneratedImageTagPolicy`가 누락된 생성 이미지 태그를 마지막 말풍선에 붙인다.
3. `ChatFlow`가 이 시점의 `messages`를 `Generation.output`에 JSON 배열로 저장한다.
4. 모델 말풍선마다 `MessageSender.send`를 호출한다. MessageSplitter는 길이를 초과한 말풍선만 추가로 나누며, 서로 다른 모델 말풍선을 합치지 않는다.
5. MessageSender가 각 조각의 이미지 첨부·타이핑·지연·취소 확인·전송·저장을 처리한다.

`[BREAK]`는 파서가 해석하는 모델 출력 계약이다. MessageSplitter는 이 태그를 해석하지 않는다. 빈 messages는 정상 무응답으로 완료하며 분할·전송을 하지 않는다. 생성 이미지가 있으면 태그 보정으로 messages를 채워 이미지만 전송할 수 있다. messages가 비어 있지 않은데 첨부로 해석되지 않는 이미지 태그만 남는 등 실제 전달이 없고 성공한 reply/react도 없으면 ChatFlow에서 실패로 처리한다.

## 분할 규칙

`MessageSplitter.split(text, maxLength)`는 문단 → 줄 → 문장 → 공백 순서로 경계를 찾고, 경계가 없으면 길이로 자른다. 짧은 입력은 그대로 반환한다. 분할한 일반 텍스트의 말풍선 가장자리 공백은 제거한다.

길이는 JavaScript `String.length`의 UTF-16 단위로 계산하고 서로게이트 쌍을 끊지 않는다. `[IMAGE:...]` 태그는 전송 전에 제거되어 첨부로 해석되므로 길이에 포함하지 않고, 태그 내부에서도 자르지 않는다. 태그를 포함한 내부 문자열은 제한을 넘을 수 있지만 실제 전송 텍스트는 제한 이하다. 마지막에 붙은 태그는 마지막 분할 조각에 남는다.

백틱 또는 물결표 3개 이상으로 시작하는 줄 단위 코드 펜스를 보호한다. 제한 이하인 블록은 통째로 유지한다. 긴 블록은 줄 경계, 마지막 수단으로 문자 수에 따라 나누고 각 조각에 언어 표기와 여닫는 펜스를 붙인다. 펜스 길이도 제한에 포함하며 코드 본문의 들여쓰기와 공백은 유지한다. 닫히지 않은 긴 블록도 조각마다 닫는다. 펜스 헤더가 너무 길면 언어 표기를 생략하고 필요 시 기본 백틱 펜스를 사용한다.

## 설정과 적용 범위

```json
"messages": {
  "maxLength": 1900
}
```

`messages.maxLength`는 기본 1900이며, 펜스 여유를 확보하는 32 이상, Discord 제한인 2000 이하의 정수만 허용한다. 잘못된 값은 RangeError로 거부한다. 논리적인 메시지의 전송을 시작할 때 설정을 읽어 해당 메시지의 모든 조각에 적용한다. 핫 리로드한 값은 다음 `send` 호출부터 반영된다.

분할은 최종 messages와 오류 안내에 적용한다. reply 도구는 별도로 텍스트 1~2000자를 검사하고, react 도구는 텍스트 전송을 하지 않는다. 길이 분할은 네트워크 오류나 다른 플랫폼 제약까지 해결하지 않는다.

## 저장과 중간 취소

`Generation.output`에는 파싱과 이미지 태그 보정을 마친 분할 전 messages가 남는다. 모델의 Markdown 원문과는 다르다. 실제 전달한 텍스트는 `Message.content`와 SENT 사건에, 이미지 정보는 `Message.attachmentsJson`에 저장한다. 이후 대화 히스토리는 실제 전달한 말풍선들을 읽는다.

각 조각 전송 전에 현재 turn과 Generation 상태를 확인한다. 중간 취소 시 확인된 전송은 저장하고 후속 조각을 보내지 않는다. 취소되어도 Generation.output에는 분할 전 전체 응답이 남는다. 상세 흐름은 [생성과 전송 및 재생성](생성과%20전송%20및%20재생성.md)을 참고한다.
