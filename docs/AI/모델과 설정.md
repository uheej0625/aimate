# 모델과 설정

ConfigManager가 `config/default.json`을 읽고 `createConfigManager`가 비어 있지 않은 환경 변수로 인증 설정을 덮어쓴다. `.env`는 진입점에서 먼저 로드한다. 실제 인증 값은 위키에 기록하지 않는다.

## provider 선택

| provider | 코드가 요구하는 설정 |
| --- | --- |
| `gateway` | `AI_GATEWAY_API_KEY` 또는 `VERCEL_OIDC_TOKEN`, Gateway 모델 ID |
| `openai` | `OPENAI_API_KEY` |
| `google` | `GOOGLE_GENERATIVE_AI_API_KEY` |
| `vertex` | `VERTEX_PROJECT_ID`, `VERTEX_LOCATION`; 이메일·private key 쌍이 있으면 명시 인증 사용, 없으면 provider 기본 인증 경로 |
| `openaiCompatible` | `baseURL`, purpose의 `apiKey` 또는 `OPENAI_COMPATIBLE_API_KEY` |
| `xai` | `XAI_API_KEY`, 선택적 `api: chat/responses` |

chat·image는 시작 시 모두 model과 prompt 및 provider별 요구 값을 검증한다. 문자열 설정의 검증 통과가 실제 모델 지원·자격증명 유효성을 보장하지는 않는다. 팩 파일은 해당 구성·사용 단계에서 읽으므로 파일 누락이 나중에 드러날 수 있다.

## 생성 설정과 도구

chat에는 `temperature`, `maxOutputTokens`, `topP`, `topK`, `maxRetries`, `providerOptions`를 전달한다. null·undefined·빈 문자열은 생략한다. image에는 해당 경로에서 size, maxRetries, providerOptions와 참조 이미지를 전달한다.

현재 native dialect는 xai만 구현되어 있고 `nativeTools.webSearch`를 제공한다. Gateway에서는 모델 ID 접두사, 직접 xai에서는 provider로 dialect를 판단한다. 명시적 dialect가 우선한다. 직접 xai native 도구에는 `api: "responses"`가 필요하다. 일반 도구와 이름이 충돌하면 오류다.

## 설정의 실제 적용 범위

| 설정 | 현재 적용 |
| --- | --- |
| `conversation.bufferTimeout` | 버퍼 생성 시 고정하는 debounce 시간 |
| `typingDelayMin/Max/PerChar` | 조각 전송의 지연 계산 |
| `maxContextMessages` | MessageRepository의 기본 조회 개수. Event 기반 모델 입력 전체의 상한은 아님 |
| `maxHistoryDays` | 현재 src에서 사용되지 않음 |
| `tools.maxSteps` | AI SDK의 stepCountIs 종료 조건. 기본 5 |
| `logging.level`, `app.environment` | 로거 수준과 development pretty 출력 |
| `logging.enableConsole/enableFile/logDirectory` | 현재 로거에서 사용되지 않음 |
| `features.*`, `discord.commandPrefix` | 현재 메시지·명령 처리의 활성화 조건으로 사용되지 않음 |
| `discord.botStatus/activityType/activityName` | 현재 ready 이벤트는 이 값 대신 고정 presence를 사용 |
| `ai.summary`, `ai.embedding` | 일반 대화 파이프라인에 연결되어 있지 않음 |

watcher가 JSON을 reload해도 인증 override 재적용이나 객체 재조립은 하지 않는다. 설정 변경은 [시작과 종료](../구조/시작과%20종료.md)의 적용 범위를 확인하고 필요 시 재시작한다.

## 설정을 읽는 코드의 역할

| 구성 요소 | 입력과 역할 |
| --- | --- |
| ConfigManager | JSON 로드·dot 경로 get, set과 파일 저장, watcher |
| createConfigManager | ConfigManager 생성 후 인증 환경 변수 적용 |
| validateAiConfig | 활성 purpose들의 missing·invalid 결과를 모아 ConfigurationError |
| getAiSettings | purpose 설정과 기본 provider 값을 구성 |
| createLanguageModel/createImageModel | provider client를 만들고 목적별 모델 반환 |
| composeDialectTools | 일반 도구와 native 도구를 결합하고 이름 충돌 검사 |

ConfigManager.get은 경로가 없으면 undefined를 반환한다. has는 값이 undefined인지 확인하므로 빈 문자열도 ‘존재’할 수 있다. 실제 자격증명 확인은 별도로 값의 truthiness를 검사한다. set은 JSON 파일에 저장하고 setInMemory는 파일에 쓰지 않는다.

## 설정 변경 예시

chat provider를 openai에서 gateway로 바꿀 때는 provider만 바꾸지 말고 Gateway 형식의 model과 인증 경로를 함께 맞춘다. image provider는 별도로 유지될 수 있으므로 시작 검증에 필요한 양쪽 인증도 확인한다.

ai.chat.maxOutputTokens가 null이면 SDK에 전달하지 않는다. 0은 null과 달리 값으로 전달되므로 ‘설정하지 않음’을 표현하려고 0을 쓰지 않는다. providerOptions의 내부 옵션 의미는 실제 사용하는 provider의 계약을 확인해야 한다.

현재 validateAiConfig의 기본 목적은 chat과 image다. summary 설정을 추가·변경해도 기본 기동 검증이 그 목적을 자동 포함하지 않는다. 새 purpose를 실제 런타임에 연결할 때 모델 생성뿐 아니라 검증·입력·출력·기록 경로를 함께 정한다.
