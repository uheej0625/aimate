# 모델과 설정

ConfigManager는 `config/default.yaml`의 일반 설정만 읽는다. `createConfigManager`는 비어 있지 않은 `VERTEX_PROJECT_ID`, `VERTEX_LOCATION`을 각각 `ai.vertex.projectId`, `ai.vertex.location`에 덮어쓴다. 최초 로드·명시적 `load()`·파일 watcher reload 모두 같은 순서이며 변경 알림에도 일반 설정만 전달한다. `.env`는 진입점에서 먼저 로드한다. 실제 인증 값은 위키에 기록하지 않는다.

기본 설정은 YAML 1.2로 읽으며 최상위는 mapping이어야 한다. 주석을 사용할 수 있고 빈 문자열은 `""`, 미지정 생성 옵션은 `null`로 명시한다. 중복 키·잘못된 YAML·mapping이 아닌 문서는 로드 실패로 처리한다. 설정 파일은 직접 편집하며 ConfigManager는 파일에 쓰지 않는다. 환경 변수 적용과 reload도 주석과 파일 내용을 바꾸지 않는다.

인증 정보는 `loadAiCredentials`가 환경 변수에서 별도 객체로 읽는다. container는 기동 시 한 번 만든 인증 스냅샷을 설정 검증과 ChatGenerator·ImageGenerator에 전달하고, 모델 생성 시 provider의 인증 옵션에만 사용한다. ConfigManager의 `getAll()`·변경 알림·프롬프트 컨텍스트에 인증 정보를 합치지 않는다. YAML의 최상위 `secrets`와 `ai.<purpose>.apiKey`는 빈 값도 허용하지 않으며 로드 실패로 처리한다. 인증 정보 변경 후에는 재시작한다.

## provider 선택

| provider | 코드가 요구하는 설정 |
| --- | --- |
| `gateway` | `AI_GATEWAY_API_KEY` 또는 `VERCEL_OIDC_TOKEN`, Gateway 모델 ID |
| `openai` | `OPENAI_API_KEY` |
| `google` | `GOOGLE_GENERATIVE_AI_API_KEY` |
| `vertex` | 일반 설정 `ai.vertex.projectId`, `ai.vertex.location`(기본 `global`); `VERTEX_CLIENT_EMAIL`·`VERTEX_PRIVATE_KEY`가 모두 있으면 명시 인증, 모두 없으면 Google Application Default Credentials |
| `openaiCompatible` | 일반 설정 `baseURL`, 인증 환경 변수 `OPENAI_COMPATIBLE_API_KEY` |
| `xai` | `XAI_API_KEY`, 선택적 `api: chat/responses` |

chat·image는 시작 시 모두 model과 prompt 및 provider별 요구 값을 검증한다. 문자열 설정의 검증 통과가 실제 모델 지원·자격증명 유효성을 보장하지는 않는다. 팩 파일은 해당 구성·사용 단계에서 읽으므로 파일 누락이 나중에 드러날 수 있다.

Gateway 인증은 `AI_GATEWAY_API_KEY`를 우선하고 없으면 `VERCEL_OIDC_TOKEN`을 사용한다. Vertex의 이메일·private key 중 하나만 설정하면 구성 오류다. 둘 다 없을 때 ADC는 Google SDK의 기본 경로를 사용하며 실제 인증 확인은 요청 시 수행한다. 로컬은 Git 제외 대상인 `.env`로 인증 정보를 제공하고, 배포는 실행 환경의 비밀 값 주입 기능을 사용한다. `.env.example`에는 변수 이름과 설명만 기록한다.

## 생성 설정과 도구

chat에는 `temperature`, `maxOutputTokens`, `topP`, `topK`, `maxRetries`, `providerOptions`를 전달한다. null·undefined·빈 문자열은 생략한다. image에는 해당 경로에서 size, maxRetries, providerOptions와 참조 이미지를 전달한다.

현재 native dialect는 xai만 구현되어 있고 `nativeTools.webSearch`를 제공한다. Gateway에서는 모델 ID 접두사, 직접 xai에서는 provider로 dialect를 판단한다. 명시적 dialect가 우선한다. 직접 xai native 도구에는 `api: "responses"`가 필요하다. 일반 도구와 이름이 충돌하면 오류다.

## 설정의 실제 적용 범위

| 설정 | 현재 적용 |
| --- | --- |
| `conversation.bufferTimeout` | 버퍼 생성 시 고정하는 debounce 시간 |
| `humanize.typingDelayMin/Max/PerChar` | Humanize가 활성 상태일 때 조각 전송의 지연 계산 |
| `humanize.enabled` | 타이핑 표시와 전송 지연 활성화. false이면 둘을 생략하며 길이 분할은 유지 |
| `messages.maxLength` | 기본 1900, 32~2000 정수. 메시지 전송 호출마다 읽으며 이미지 태그 제거 후 텍스트와 코드 펜스 길이를 제한 |
| `maxContextMessages` | MessageRepository의 기본 조회 개수. Event 기반 모델 입력 전체의 상한은 아님 |
| `maxHistoryDays` | 현재 src에서 사용되지 않음 |
| `tools.maxSteps` | AI SDK의 stepCountIs 종료 조건. 기본 5 |
| `logging.level`, `app.environment` | 로거 수준은 YAML reload 뒤 적용. development pretty 출력 방식은 시작 시 결정. [로그](../운영/로그.md) 참고 |
| `features.*`, `discord.commandPrefix` | 현재 메시지·명령 처리의 활성화 조건으로 사용되지 않음 |
| `ai.summary`, `ai.embedding` | 일반 대화 파이프라인에 연결되어 있지 않음 |

watcher는 YAML과 Vertex의 일반 설정 override만 다시 읽으며 인증 스냅샷을 변경하지 않는다. 객체를 재조립하거나 `.env` 파일을 다시 읽지도 않는다. 설정 변경은 [시작과 종료](../구조/시작과%20종료.md)의 적용 범위를 확인하고 필요 시 재시작한다.

Discord 프레즌스는 YAML 설정으로 관리하지 않는다. 시작 시 온라인·활동 없음이며 이후 AI가 `set_discord_status`·`set_discord_activity` 도구로 각각 변경한다. 변경은 저장하지 않고 재시작 시 초기화한다. 상세 계약은 [Discord 프레즌스](../플랫폼/Discord.md#봇-프레즌스)를 참고한다.

메시지 길이 제한은 send 호출마다, Humanize 활성 여부와 지연은 조각마다 최신 설정을 읽으므로 객체를 다시 조립하지 않아도 변경이 반영된다. [메시지 분할](../대화/메시지%20분할.md)과 [Humanize](../대화/Humanize.md)에서 각각의 계약을 확인한다.

## 설정을 읽는 코드의 역할

| 구성 요소 | 입력과 역할 |
| --- | --- |
| ConfigManager | YAML 로드·dot 경로 get, 메모리 값 변경, watcher |
| createConfigManager | 매 YAML 로드 후 Vertex의 일반 설정 환경 변수를 적용 |
| loadAiCredentials | 알려진 AI 인증 환경 변수만 읽어 변경 불가능한 별도 객체 생성 |
| validateAiConfig | 일반 설정과 별도 인증 객체로 활성 purpose들을 검증하고 missing·invalid 결과를 모아 ConfigurationError |
| getAiSettings | purpose 설정과 기본 provider 값을 구성 |
| createLanguageModel/createImageModel | provider client를 만들고 목적별 모델 반환 |
| composeDialectTools | 일반 도구와 native 도구를 결합하고 이름 충돌 검사 |

ConfigManager.get은 경로가 없으면 undefined를 반환한다. has는 값이 undefined인지 확인하므로 빈 문자열도 ‘존재’할 수 있다. 실제 자격증명 확인은 별도로 값의 truthiness를 검사한다. setInMemory는 메모리만 변경한다. 파일 저장용 save·set·delete·reset API는 제공하지 않는다.

## 설정 변경 예시

chat provider를 openai에서 gateway로 바꿀 때는 provider만 바꾸지 말고 Gateway 형식의 model과 인증 경로를 함께 맞춘다. image provider는 별도로 유지될 수 있으므로 시작 검증에 필요한 양쪽 인증도 확인한다.

ai.chat.maxOutputTokens가 null이면 SDK에 전달하지 않는다. 0은 null과 달리 값으로 전달되므로 ‘설정하지 않음’을 표현하려고 0을 쓰지 않는다. providerOptions의 내부 옵션 의미는 실제 사용하는 provider의 계약을 확인해야 한다.

현재 validateAiConfig의 기본 목적은 chat과 image다. summary 설정을 추가·변경해도 기본 기동 검증이 그 목적을 자동 포함하지 않는다. 새 purpose를 실제 런타임에 연결할 때 모델 생성뿐 아니라 검증·입력·출력·기록 경로를 함께 정한다.
