# 캐릭터

`config/default.json`의 `character`가 활성 캐릭터 ID다. ID는 소문자·숫자로 시작하고 이후 소문자·숫자·하이픈을 허용한다. 캐릭터별 대화 사건과 처리 cursor는 이 ID로 구분한다.

## 파일과 구성

| 파일 | 역할 |
| --- | --- |
| `content/characters/<id>/variables.json` | 캐릭터 변수와 선택적 생일·입학 연도·시간대 |
| `content/characters/<id>/identity.md` | 변수를 사용해 렌더링하는 identity 템플릿 |
| `content/characters/<id>/reference.png` | 셀피 생성 시 필수 기준 이미지 |

CharacterContextBuilder는 variables를 읽어 나이·생년월일 표기·학년을 계산하고 identity를 렌더링한다. birthday는 `{year, month, day}`, schoolEnrollment는 `year`를 사용한다. 학년은 3월 기준 학년도에서 계산해 1~3으로 제한한다.

variables 파일이 없으면 경고 후 빈 변수로 계속하지만 잘못된 JSON은 오류다. identity 파일은 필수다. 캐릭터 경로는 생성자에서 고정하고 내용은 build 때 읽으므로 ID 변경은 재시작해야 한다.

## Discord 계정과의 관계

토큰 이름은 `AIMATE_DISCORD_<정규화한 ID>_TOKEN`이다. 예를 들어 `alice-v2`는 `AIMATE_DISCORD_ALICE_V2_TOKEN`을 사용한다. 봇 PlatformAccount는 실제 플랫폼 봇 ID로 준비하고, 캐릭터 ID와 플랫폼 계정 ID를 같은 것으로 취급하지 않는다.

캐릭터 변경이 DB Message를 다른 캐릭터의 기록으로 이관하는 작업은 아니다. 기존 채널의 현재 Message를 새로운 캐릭터가 HISTORY로 읽을 수 있으며, Event와 ConversationState는 캐릭터별로 분리된다.

## CharacterContextBuilder를 따라 읽기

생성자는 identityPath와 variablesPath를 절대 경로로 고정한다. build는 loadVariables → buildCharacterData → renderIdentity 순서로 실행한다. buildCharacterData는 입력 변수에 계산한 age·schoolGrade·birthDate를 덧붙이고, renderIdentity는 character와 system 네임스페이스로 identity 템플릿을 렌더링한다.

birthDate는 표시 문자열이고 birthday는 날짜 구조다. 나이는 생일이 지났는지 비교해 계산한다. schoolGrade는 입학 연도와 3월 경계로 계산하는 현재 구현 규칙이며 모든 학교 체계를 일반화한 값이 아니다.

계산 기준 Date는 전달한 system.now.raw에서 만들고 날짜의 연·월·일은 캐릭터 timezone을 사용해 읽을 수 있다. 생일 경계나 시간대 문제를 바꿀 때에는 채팅의 app.timezone과 캐릭터 timezone 중 어느 값을 사용하는지 나눠 확인한다.

## 캐릭터를 추가했는데 실행이 안 되는 경우

ID 형식 오류와 파일 누락은 다른 문제다. 유효한 ID라도 identity.md가 없으면 템플릿 로드가 실패한다. variables가 없으면 경고로 계속하고, reference.png 누락은 셀피 도구 실행에서 실패한다. 파일 요구 조건을 모두 같은 시작 검증으로 설명하지 않는다.

봇 이름·handle은 PlatformAccount 표시 정보이고 identity는 모델 입력용 캐릭터 설명이다. identity를 바꿨다고 Discord 표시 이름이나 계정 정보가 자동으로 같은 내용으로 바뀌는 것은 아니다.
