# 도구와 이미지

ToolRegistry는 `src/tools/definitions/`의 JS 모듈을 이름순으로 읽어 default export를 등록한다. 정의에는 name·description·inputSchema·execute가 필요하다. 모듈 로드 실패는 기록하고 다른 파일 로드를 계속하므로 시작 성공만으로 모든 도구가 등록되었다고 판단하지 않는다.

## 모델에 노출되는 도구

| 이름 | 플랫폼 | 역할 |
| --- | --- | --- |
| `get_current_time` | 전체 | 시각 조회 |
| `fetch_url` | 전체 | URL 본문 추출 |
| `set_presence_status` | Discord | 온라인 presence 설정 |
| `set_status_message` | Discord | activity 메시지 설정 |
| `generate_photo` | 전체 | kind에 따라 일반 사진 또는 셀피 생성 |
| `generate_selfie` | 전체 | 별도 셀피 도구 |
| `generate_screenshot` | 전체 | 스크린샷 스타일 이미지 생성 |

`enabled`, `platforms`, `requires` 조건을 모두 만족해야 노출한다. 일반 requires는 `secrets.<service>ApiKey`를 확인하고 `image`는 `ai.image.model` 존재 여부를 확인한다. 이 필터는 이미지 provider 전체의 인증·모델 유효성 검사 대신 사용할 수 없다.

ToolExecutionContextFactory는 설정, 채널 DB record, 플랫폼 client, 이미지 생성기, GenerationRepository, 캐릭터 ID, 요청 시각과 abortSignal을 전달한다. 실행 오류는 Registry에서 `{error}`로 바꿔 모델에 반환한다. SDK native xai 검색은 별도 dialect 도구이며 일반 fetch_url과 다르다.

모델이 native 도구 호출 없이 전체 응답을 `{name, arguments}` JSON으로 보내면 ai/chat의 회수 경로가 등록된 일반 도구를 직접 실행할 수 있다. 이 경로는 두 번째 모델 응답을 생성하지 않고 도구의 message/error 또는 기본 문구를 사용한다. 프롬프트 비교 검사는 이를 정상 계약 준수로 인정하지 않는다.

## 이미지 생성과 전달

1. sourceImages와 셀피 기준 이미지 존재를 확인하고 도구별 템플릿을 렌더링한다.
2. IMAGE Generation을 PROCESSING으로 만들고 AI SDK 이미지 호출에 abortSignal을 전달한다.
3. `content/image/<8자리 hex>.png`를 쓰고 PROCESSING 상태에서만 COMPLETED와 출력 파일명을 저장한다.
4. 도구 결과가 `[IMAGE:<id>]` 포함을 지시한다. GeneratedImageTagPolicy는 빠진 생성 이미지 태그를 보완한다.
5. AttachmentResolver가 8자리 hex ID·완료된 IMAGE record·로컬 일반 파일을 확인해 첨부로 변환한다.

중단은 CANCELLED, 생성 오류는 FAILED로 기록한다. IMAGE의 COMPLETED는 파일 생성 완료이며 CHAT의 메시지 전달 완료와 다르다. 파일을 쓴 뒤 취소되면 미사용 파일이 남을 수 있고 자동 정리 worker는 없다.

generate_photo의 selfie와 generate_selfie는 활성 캐릭터 `reference.png`를 요구한다. 이미지 시간대는 현재 runner에서 `ai.image.timeZone → app.timeZone → Asia/Seoul` 순으로 조회한다. 일반 채팅의 `app.timezone`과 키 대소문자가 다르다.

입력 어댑터는 사용자 첨부를 자동으로 모델에 전달하지 않는다. sourceImages는 로컬 생성 이미지 참조용이다. CLI 모의 채널은 텍스트만 표시하고 이미지 files를 렌더링하지 않는다.

## 실행 단계별 클래스

| 구성 요소 | 맡은 경계 |
| --- | --- |
| ToolRegistry | 정의 등록 → 활성 목록 → AI SDK ToolSet |
| ToolExecutionContextFactory | 요청별 의존성과 플랫폼 client 제공 |
| ChatGenerator와 ai/chat | 모델 호출, 다단계 결과 수집, 응답 파싱과 태그 보완 |
| ImageGenerationToolRunner | 템플릿·참조 이미지·DB 상태·파일 쓰기를 조정 |
| ImageGenerator와 ai/images | provider별 SDK 이미지 요청과 바이트 반환 |
| GeneratedImageTagPolicy | 성공한 도구 결과의 이미지 참조를 최종 메시지에 유지 |
| GeneratedImageAttachmentResolver | 참조를 검증해 실제 파일 첨부로 바꿈 |
| HistoryMessageFormatter | 저장한 이미지 첨부를 이후 대화용 설명으로 변환 |

태그 보완과 파일 첨부 검증은 역할이 다르다. 성공 도구가 imageId를 반환하면 태그를 보완할 수 있지만, 전달 시 파일이 없거나 완료 record를 찾지 못하면 첨부하지 않는다. 모델이 임의 태그를 출력했다는 이유만으로 임의 로컬 파일을 보내지 않는다.

## 요청에서 결과까지 예시

사용자가 일반 사진을 요청하면 generate_photo의 kind=photo 경로가 photo.md를 사용한다. kind=selfie라면 selfie.md와 캐릭터 reference.png를 사용한다. 같은 도구 이름이어도 템플릿·참조 입력·옵션이 달라진다.

Runner의 결과에는 imageId, generationId, outputPath와 모델용 instruction이 들어간다. 화면 전송에는 outputPath를 모델이 직접 지정하게 하지 않고 IMAGE 태그를 해석한다. 저장한 generated_image 첨부 metadata에는 imageId·filename·generationId를 남겨 다음 대화에서 생성 프롬프트를 조회할 수 있게 한다.

## 오류 위치를 나눠 보기

참조 이미지 확인과 템플릿 렌더링은 IMAGE Generation 생성보다 앞서 실행된다. 이 단계의 실패는 도구 오류로 반환되며 실패한 IMAGE row 자체가 없을 수 있다.

IMAGE row를 만든 이후 SDK·파일 저장 단계가 실패하면 FAILED 또는 CANCELLED로 기록한다. 파일 생성 성공과 메시지 전달 성공은 별개이므로 COMPLETED 이미지가 있어도 사용자 화면에 표시되지 않을 수 있다.

ToolRegistry는 execute 오류를 모델용 error 결과로 바꾼다. 도구 오류가 발생했다고 항상 전체 CHAT이 FAILED가 되는 것은 아니다. 모델이 그 오류를 읽고 설명 메시지를 정상 생성할 수도 있다.
