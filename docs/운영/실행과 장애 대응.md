# 실행과 장애 대응

## PM2 실행

프로젝트 루트에서 실행한다. PM2는 package.json의 의존성이 아니므로 운영 환경에 별도로 준비한다.

```powershell
pm2 startOrRestart ecosystem.config.cjs --only aimate
pm2 save
pm2 logs aimate
```

ecosystem은 Discord 진입점과 프로젝트 cwd를 지정한다. ConfigurationError는 Discord 시작 경로에서 종료 코드 78로 종료하며 `stop_exit_codes: [78]`로 자동 재시작하지 않는다. 일반 기동 실패는 코드 1이다.

재시도 간격은 5초, 최소 안정 실행 판단은 30초, 짧은 실행 실패의 max_restarts는 5다. 전체 누적 재시작 5회 제한으로 해석하지 않는다. 설정 수정 뒤 `pm2 restart aimate`로 적용한다.

## 로그와 생성 기록

Pino는 logging.level을 사용하고 development에서는 pretty 출력한다. `logging.enableFile`과 logDirectory로 앱 자체 파일 로깅이 켜지지 않는다. 운영 stdout/stderr 수집은 PM2 등 실행 환경에서 관리한다. CLI TTY는 화면 보호를 위해 로그가 silent다.

Generation에는 input·output, apiRequest·apiResponse, status, createdAt, sentAt, discardedAt이 남는다. Discord 메시지 메뉴 ‘생성 정보 확인’은 연결된 Generation을 요약한다. 상세 원인은 로그의 module·Generation 정보와 DB 기록을 함께 확인한다.

## 증상별 확인

| 증상 | 확인 순서 |
| --- | --- |
| 코드 78로 시작 실패 | chat·image provider 인증 필드, model·prompt, nativeTools, 캐릭터 ID, Discord 토큰 이름 |
| 기동 뒤 팩 오류 | chat/sequence.js와 참조 파일, identity, image 템플릿 존재 여부 |
| Discord에서 무응답 | 현재 채널 등록, 봇 작성 여부, intent·채널 권한, 버퍼 시간, 생성 로그 |
| 긴 대화 모델 오류 | Event 전체 컨텍스트의 토큰 한도. maxContextMessages로 자동 제한된다고 가정하지 않음 |
| 응답 도중 끊김 | 새 turn·수정·삭제로 CANCELLED인지, 플랫폼 전송 실패로 FAILED인지 |
| 이미지 미표시 | 완료 IMAGE record, content/image 파일, 유효 태그, 셀피 reference.png. CLI는 첨부 렌더링 미지원 |
| 설정 변경 미적용 | 생성자 고정 값·sequence import 캐시·reload 인증 override 범위 확인 후 재시작 |
| 재생성 출력 일부 잔존 | Discord 삭제 실패와 discardedAt, 명령 결과·로그 확인 |

정상 종료는 타이머 정리·abort·진행 Generation 취소·연결 종료를 수행한다. 강제 종료 뒤 남은 진행 상태를 자동 복구하는 worker는 없다. 일반 메시지 삭제는 soft delete라 과거 snapshot을 지우지 않으며, 실패한 출력이나 미사용 이미지도 자동 청소하지 않는다.

## Generation 상태별로 조사하기

| 상태 | 이미 일어난 단계 | 먼저 확인할 자료 |
| --- | --- | --- |
| PROCESSING | Generation 생성. 입력 저장 또는 모델 호출 진행 가능 | input 존재, 시작 로그, 진행 요청 |
| GENERATED | 모델 출력과 기록 저장 | output, 플랫폼 send·저장 오류와 새 turn |
| COMPLETED | CHAT은 전송 완료와 cursor 반영. IMAGE는 파일 생성 완료 | sentAt 또는 출력 파일, 실제 메시지 연결 |
| CANCELLED | 진행 작업이 현재 소유권을 잃거나 abort됨 | 새 입력·편집·삭제와 취소 reason |
| FAILED | 현재 작업이 실패 경로로 진행 | 모델·템플릿·전송·DB 오류와 fallback |

상태만으로 실패 위치를 단정하지 않는다. PROCESSING인데 input이 없다면 입력 준비 이전 또는 기록 실패일 수 있고, GENERATED인데 일부 Message가 있으면 부분 전송 뒤 중단됐을 수 있다.

GetGenerationInfo는 화면용 inputMessages·outputMessages를 구성하며 JSON 파싱 실패는 빈 목록으로 처리한다. 빈 표시가 항상 실제 입력 없음을 뜻하지 않으므로 상세 장애는 원본 Generation 기록을 확인한다.

## 문제를 좁히는 순서

먼저 platform과 플랫폼 채널 ID를 확인하고 내부 Channel.id를 찾는다. 다음 Message의 generationId와 생성 시각을 확인한다. Event의 source·kind와 snapshot 범위를 보면 새 입력이 저장되었는지, 경험으로 관찰되었는지, 처리되었는지 구분할 수 있다.

취소는 새 대화 입력을 반영하기 위한 정상 동작일 수 있다. 동일 채널에서 연속 입력이 있으면 취소 기록만으로 장애라고 판단하지 않는다. 실패로 분류할 경우 입력 준비·모델·전송·저장 중 어느 경계에서 발생했는지 로그와 함께 기록한다.

API metadata에는 system·messages·도구 결과와 provider 응답이 포함될 수 있다. 인증 값과 비공개 대화가 들어 있지 않은지 확인한 후 필요한 부분만 공유한다. 일반 metadata 직렬화는 자동 비밀 제거 기능이 아니다.
