# 로그

현재 구현은 Pino 구조화 로그를 stdout으로 출력한다. `app.environment: "development"`에서는 pino-pretty로 읽기 쉽게 표시한다. 운영 로그의 보관·회전·수집은 PM2 등 실행 환경이 담당한다. 앱 자체 파일 로깅 설정은 없다. CLI가 TTY에서 실행되면 대화 화면을 보호하기 위해 로그를 `silent`로 유지한다. CLI 로그가 필요하면 stdout을 파일이나 파이프로 전달한다.

## 설정과 레벨

`config/default.json`의 `logging.level` 기본값은 `info`다. 설정 파일 watcher가 활성화된 실행에서는 JSON reload 뒤 기존 모듈 로거에도 새 레벨이 적용된다. `app.environment`에 따른 pretty 출력 방식은 시작 시 결정하므로 변경 후 재시작한다. 설정 값·인증 값 전체를 출력하지 않는다.

| 레벨 | 기록하는 내용 |
| --- | --- |
| `debug` | 메시지 수신·큐 대기·처리·건너뜀 사유, turn 생성, 버퍼 예약·교체·실행·해제, 생성 단계 시작과 소요 시간, 모델 step 요약, abort 요청, 타이핑 지연, 조각별 전송·저장, 메시지 작업 영수증 재사용 |
| `info` | 앱 시작·종료, 봇 계정·플랫폼 준비, CHAT/IMAGE 생성 시작·완료·취소, 모델 호출 시작·완료, 도구 실행 시작·완료, 명령 핸들러 시작·완료 |
| `warn` | 모델 호출 실패 요약·경고 개수, 오류 결과를 반환한 도구, 전송 후 저장 재시도, 이미지 첨부 누락, 대체 처리로 전환하는 상황 |
| `error` / `fatal` | 생성 실패와 실패 단계, 도구 실행 예외, 전송·저장 실패, 오류 안내 전송 실패, 설정·플랫폼·이벤트 오류. 시작·커맨드 배포 실패는 fatal |

새 입력 때문에 이전 작업이 취소되는 것은 정상 흐름이다. 생성 취소는 `info`, 모델·도구의 abort와 abort 요청은 `debug`로 남긴다. 도구가 예외를 던지지 않아도 `error` 결과, `success: false`, `status: "error"/"failed"`이면 실패로 분류한다. 도구의 입력·결과 원문은 출력하지 않으며 반환된 오류 결과의 상세는 저장된 API 메타데이터와 함께 조사한다.

## 공통 필드와 연결

`event`는 검색에 사용하는 고정 이름이고 `msg`는 사람이 읽는 설명이다. 공통으로 ISO 시각 `time`, `level`, `module`이 있으며 실행 범위에 따라 다음 필드가 붙는다.

| 필드 | 의미 |
| --- | --- |
| `platform`, `platformChannelId` | Discord/CLI와 플랫폼 채널 ID |
| `channelId` | 내부 Channel.id. 등록 채널 조회 뒤 사용할 수 있음 |
| `turnId` | 채널의 응답 소유권을 식별하는 UUID. 버퍼 교체와 재생성을 구분 |
| `generationId`, `generationType` | 해당 CHAT/IMAGE 생성 기록 |
| `parentGenerationId` | 이미지 생성을 요청한 CHAT 생성 ID |
| `rerollGenerationId` | 재생성에 사용한 이전 CHAT 생성 ID |
| `toolName`, `toolCallId` | 도구와 SDK의 호출 ID. 텍스트 도구 호출 복구 등 호출 ID가 없는 실행도 있음 |
| `platformMessageId` | 입력·전송·저장·삭제 대상 메시지 ID. 수신 데이터에 따라 없는 경우도 있음 |
| `interactionId`, `commandName`, `platformUserId` | Discord 명령 실행 정보 |
| `durationMs`, `queueWaitMs`, `delayMs` | 단조 시계로 측정한 소요·대기 시간 또는 설정에 따라 계산한 타이핑 지연 |

AsyncLocalStorage로 비동기 실행 범위에 식별자를 전달한다. 동시 채널의 식별자가 섞이지 않으며, 이미지 생성에서는 자체 generationId를 사용하고 호출한 CHAT ID를 parentGenerationId로 남긴다. 이미지 생성이 끝나면 도구·CHAT 로그는 원래 범위로 돌아온다. 생성 기록이 만들어지기 전 오류에는 generationId가 없을 수 있다.

## 주요 이벤트

| 이벤트 | 확인할 내용 |
| --- | --- |
| `message.skipped`, `message.processed` | 미등록 채널·봇 작성자·변경 없음·관찰 시간 밖인지, 응답 예약 여부 |
| `buffer.scheduled`, `buffer.fired` | 예약 교체 여부, 설정된 timeout과 실제 대기 시간 |
| `generation.requested`, `generation.started` | 요청과 실제 생성 시작. stale turn은 `generation.skipped` |
| `generation.stage.started/completed` | `prepare_input`, `model`, `record_output`, `delivery`, `complete` 단계. 초기 준비 완료는 `start` 단계 |
| `generation.completed` | 총 시간, CHAT 메시지 개수와 실제 전달 여부. IMAGE는 이미지 ID·크기 |
| `generation.cancelled` | 취소 reason과 발생 stage. 일부 전달 후 취소됐다면 delivered가 true일 수 있음 |
| `generation.failed` | 실패 stage와 오류. CHAT은 해당 단계 시간도 기록 |
| `model.started/completed` | provider·model, 소요 시간. CHAT은 finishReason·step 개수·토큰 수·도구 호출 수, IMAGE는 이미지 크기와 제공된 토큰 수 |
| `model.step.completed`, `model.warnings` | step별 요약과 provider 경고 개수. 프롬프트·경고 원문은 출력하지 않음 |
| `tool.started/completed/failed/cancelled` | 도구 실행 결과와 소요 시간 |
| `message.send.started/completed/failed` | 실제 플랫폼 전송. chunkIndex는 0부터 시작 |
| `message.storage.retry/completed/failed` | 플랫폼 전송 확인 뒤 DB 저장. 저장 재시도는 메시지를 다시 보내지 않음 |
| `message.action.confirmed`, `message.action.reused` | reply/react 전달 확인 또는 기존 작업·영수증 재사용 |
| `generation.fallback.sent/skipped/failed` | 생성 실패 뒤 사용자 안내 처리 결과 |

`generation.completed`의 `messageCount: 0, delivered: false`는 정상적인 침묵이다. reply/react만 실행한 경우 메시지 개수가 0이어도 delivered는 true일 수 있다. `command.completed`는 명령 핸들러가 반환됐다는 뜻이며, 핸들러 내부에서 처리한 실패는 개별 오류 이벤트도 함께 확인한다.

모델의 `durationMs`는 SDK 호출 전체 시간으로 내부 재시도와 도구 실행이 포함될 수 있다. 세부 네트워크 요청별 재시도 횟수를 기록하는 것은 아니다. 토큰 필드는 provider가 반환한 경우에만 존재한다. `Generation` DB의 상태·입력·출력·API 기록과 로그는 별도 자료이며 로그 저장 실패를 DB 트랜잭션과 묶지 않는다.

## 장애 조사

먼저 `platformChannelId`로 채널을 찾고 `turnId`와 `generationId`로 요청을 좁힌다. `generation.failed.stage`나 마지막 `generation.stage.started`를 확인하면 입력 준비·모델·전송·저장 중 어디에서 멈췄는지 조사할 수 있다. 이미지 문제는 parentGenerationId를 통해 IMAGE 기록까지 따라간다.

`message.send.completed` 뒤 `message.storage.failed`가 있으면 사용자는 이미 메시지를 받았지만 저장은 실패한 상태다. `generation.cancelled`는 reason과 새 turn의 시작을 함께 확인한다. 수신 이후 생성이 시작되지 않았다면 `debug`로 올려 `message.skipped`, `message.processed`, `buffer.scheduled/fired`, `generation.skipped`를 확인한다.

```powershell
pm2 logs aimate --lines 200
```

일반 로그는 메시지·프롬프트·도구 입력 및 결과·응답 본문을 통째로 출력하지 않는다. 오류는 type·message·stack·code·statusCode·isRetryable과 제한된 cause를 직렬화한다. SDK 재시도 실패는 reason·실패 시도 개수와 마지막 오류도 보존한다. SDK 오류의 request·response·headers 같은 부가 객체는 제외한다. `secrets` 및 최상위/한 단계 아래의 알려진 인증 필드·headers는 마스킹한다. 임의 문자열, 오류 message·stack 안에 포함된 비밀까지 자동 제거하는 기능은 아니므로 오류 메시지에 사용자 본문이나 인증 값을 직접 넣지 않는다. 상세 API 기록 공유 시에는 [실행과 장애 대응](실행과%20장애%20대응.md)의 주의사항도 따른다.
