# 설정과 콘텐츠

실행 설정은 YAML, 인증 값은 환경 변수, 캐릭터와 프롬프트는 `content/`에 둔다. 먼저 바꾸려는 대상에 맞는 파일을 고른다.

| 바꾸려는 것 | 파일 |
| --- | --- |
| 실행할 캐릭터·연결, 모델, 대기 시간 | [config/default.yaml](../config/default.yaml) |
| API 키와 Discord 토큰 | `.env` 또는 실행 환경의 환경 변수. 이름은 [.env.example](../.env.example) 참고. |
| 캐릭터 시간대 | `content/characters/<id>/config.json` |
| 프로필 데이터·정체성·말투 | 같은 폴더의 `variables.json`, `identity.md` |
| 모델 입력 순서·지시문 | `content/prompts/<팩>/chat/sequence.js`와 참조 Markdown |
| 이미지 생성 지시문 | `content/prompts/<팩>/image/photo.md`, `selfie.md`, `screenshot.md` |
| 응답 판단 지시문·행동별 기준 | `content/prompts/<팩>/decision/prompt.json` |

## 캐릭터 목록과 설정 덮어쓰기

```yaml
character: demo # CLI 기본 선택
characters:
  - id: demo
    connections:
      discord: {}
      cli: {}
    settings:
      humanize:
        enabled: false
  - id: sora
    connections:
      discord: {}
    settings:
      conversation:
        bufferTimeout: 3000
```

최상위 설정이 공통 기본값이다. `characters[].settings`에서 `ai`, `conversation`, `messages`, `humanize`, `features`, `tools`를 캐릭터별로 덮어쓴다. 객체는 재귀 병합하고 배열과 명시적인 `null`은 교체한다.

ID는 소문자 영문·숫자로 시작하고 소문자 영문·숫자·하이픈을 사용한다. `connections`는 현재 `discord: {}`, `cli: {}`를 지원한다. 각 캐릭터에는 하나 이상의 연결이 필요하며 같은 ID를 중복 선언할 수 없다.

Discord 토큰 이름은 `AIMATE_DISCORD_<ID>_TOKEN`이다. 예를 들어 `demo-v2`는 `AIMATE_DISCORD_DEMO_V2_TOKEN`을 사용한다. `npm start`는 Discord 연결이 있는 목록 전체를 실행하고, `--character`는 그중 하나를 고른다.

구현: [characters.js](../src/config/characters.js), [config/index.js](../src/config/index.js), [selection.js](../src/config/selection.js), [Discord credentials.js](../src/platforms/discord/credentials.js).

## 모델과 인증

`ai.chat`, `ai.image`, `ai.decision`에는 `provider`, `model`, `prompt`를 지정한다. `model`은 해당 provider가 받는 식별자이고, `prompt`는 로컬 팩 이름이다. Decision은 현재 `provider: gateway`만 지원한다. 기본 YAML의 모델과 프롬프트를 자신의 계정·콘텐츠에 맞춰 확인한다.

| provider | 인증 환경 변수 | 추가 설정 |
| --- | --- | --- |
| `gateway` | `AI_GATEWAY_API_KEY`, 없으면 `VERCEL_OIDC_TOKEN` | 모델 ID는 `openai/...`처럼 Gateway 형식. |
| `openai` | `OPENAI_API_KEY` | OpenAI 직접 연결. |
| `google` | `GOOGLE_GENERATIVE_AI_API_KEY` | Google 직접 연결. |
| `vertex` | Application Default Credentials 또는 `VERTEX_CLIENT_EMAIL` + `VERTEX_PRIVATE_KEY` | `ai.vertex.projectId`, `ai.vertex.location`. 이메일과 키는 함께 설정한다. |
| `openaiCompatible` | `OPENAI_COMPATIBLE_API_KEY` | 해당 목적의 `baseURL` 필수. |
| `xai` | `XAI_API_KEY` | `api`는 `chat` 또는 `responses`. 서버 도구 사용 시 `responses`. |

이는 설정 검증에서 허용하는 provider 목록이다. 사용할 모델이 채팅·이미지 등 해당 목적을 지원하는지는 별도로 확인해야 한다.

일반 설정의 환경 변수 덮어쓰기는 `VERTEX_PROJECT_ID`, `VERTEX_LOCATION`에 적용된다. 그 외 임의의 환경 변수 이름이 YAML 설정에 자동 대응하지는 않는다. `.env`보다 이미 실행 환경에 설정된 변수가 우선한다.

`temperature`, `maxOutputTokens`, `topP`, `topK`, `maxRetries`, `providerOptions`는 AI 호출 설정이다. `null`인 생성 옵션은 요청에서 제외한다. `nativeTools`는 provider의 서버 도구이고, `src/tools/definitions/`의 애플리케이션 도구와 별도로 처리한다. dialect와 서버 도구 조합은 [ai/dialects.js](../src/ai/dialects.js)가 검증한다.

AI 인증은 시작 시 별도 snapshot으로 읽는다. YAML의 `secrets`나 `ai.<목적>.apiKey`는 거부하며, 일반 템플릿 설정에 인증을 합치지 않는다. 시작 시 chat과 image 설정을 모두 검증한다. `conversation.responseMode: decision`이면 `ai.decision`과 Gateway 인증도 검증한다. buffer 모드는 Decision 인증 없이 사용할 수 있다. [응답 판단](응답%20판단.md)에 설정 예시와 동작을 정리했다.

구현: [ai/config.js](../src/ai/config.js), [ai/credentials.js](../src/ai/credentials.js), [ai/models.js](../src/ai/models.js).

## 응답 타이밍과 길이

| 설정 | 기본값 | 의미 |
| --- | --- | --- |
| `conversation.responseMode` | `buffer` | `buffer` 또는 `decision` 선택. |
| `conversation.bufferTimeout` | `5000` ms | buffer 모드에서 마지막 입력 뒤 생성까지 기다리는 시간. |
| `conversation.decision.debounceMs` / `maxWaitMs` | `1000` / `5000` ms | Decision 모드의 입력 묶기와 연속 입력의 최대 대기 시간. debounce는 0 허용. |
| `conversation.decision.recheckMs` | `5000` ms | `wait` 후 첫 재평가의 기준 간격. `respond`와 확률이 비슷하면 최대 절반까지 줄인다. |
| `conversation.decision.recheckMultiplier` | `2` | 연속 `wait` 시 재평가 간격 증가 배수. 1보다 큰 유한수. |
| `conversation.decision.maxRecheckMs` | `30000` ms | 반복 재평가 간격 상한. |
| `features.enableDM` | `true` | Discord 1:1 DM 대화 허용. 캐릭터별 설정을 적용하며 재시작이 필요하다. |
| `messages.maxLength` | `1900` | 한 번에 전송할 텍스트의 길이 한도. 연결 한도와 작은 값을 사용한다. |
| `humanize.enabled` | `true` | 타이핑 표시와 전송 지연 사용. |
| `humanize.typingDelayMin` / `typingDelayMax` | `1000` / `2000` ms | 타이핑 지연의 범위. |
| `humanize.typingDelayPerChar` | `60` ms | 글자 수에 따른 지연 계산값. |
| `tools.maxSteps` | `5` | AI SDK의 도구 사용을 포함한 생성 단계 한도. |
| `logging.level` | `info` | 일반 로그의 출력 레벨. |

`messages.maxLength`는 32 이상 정수다. Humanize를 꺼도 길이 분할은 수행한다. Discord의 연결 한도는 2000자이며 CLI는 별도 텍스트 상한이 없다.

YAML의 `conversation.maxContextMessages`, `maxHistoryDays`는 **현재 Event 기반 모델 문맥의 자동 제한으로 작동하지 않는다.** 전체 관찰이 길어지면 모델 한도에 도달할 수 있다. `ai.summary`, `ai.embedding` 설정과 `Memory` 모델이 있어도 장기 기억 파이프라인이 연결된 것은 아니다.

## 캐릭터 템플릿

`config.json`의 `timezone`은 필수 IANA 시간대다. 관찰의 시각 표시, 프롬프트의 현재 시각, 생일에 따른 나이와 학년 계산에 같은 시간대를 사용한다. 날짜 표시 언어는 `app.language`를 따른다.

`variables.json`의 데이터를 `character.*`로 제공하고, `identity.md`를 렌더링해 `character.identity`를 만든다. 변수 파일이 없으면 빈 객체로 진행하지만 `config.json`과 identity가 필요한 경로에서는 해당 파일을 준비해야 한다.

프롬프트 템플릿은 다음 이름으로 데이터를 읽는다.

| 이름 | 내용 |
| --- | --- |
| `character.*`, `character.identity` | 프로필과 렌더링한 정체성. |
| `system.now.*` | 캐릭터 시간대의 현재 시각. `raw`는 오프셋을 포함한 ISO 8601. |
| `config.*` | 인증과 분리된 캐릭터별 일반 설정. |
| `data.*`, `runtime.*` | 호출 시 공급한 작업 데이터와 런타임 문맥. |

구현: [CharacterContextBuilder.js](../src/character/CharacterContextBuilder.js), [PromptComposer.js](../src/chat/context/PromptComposer.js), [templateContext.js](../src/utils/templateContext.js).

## 채팅 프롬프트 팩

`chat/sequence.js`는 순서를 가진 배열을 default export한다. 다음은 공개 테스트 자료와 같은 최소 구성이다.

```js
export default [
  { type: "file", role: "system", source: "system.md" },
  { type: "placeholder", role: "user", source: "character.identity" },
  { type: "history" },
  { type: "response", sources: ["response.md"] },
  { type: "pending" },
];
```

`file`은 팩의 파일, `text`는 문자열, `placeholder`는 템플릿 값을 렌더링한다. `history`와 `pending`은 관찰 기록을 배치한다. `response`는 참조 지시문에 현재 시각·참여자·관찰 표시 규칙을 붙인다.

system 역할의 단계는 정확히 하나여야 한다. 파일 경로는 해당 팩의 `chat/` 기준이며 실제 파일이 있어야 한다. `cache-point`는 현재 아무 작업도 하지 않는다. `summary`, `fact`, `episode` 단계는 지원하지 않는다.

응답 본문은 `## messages` 아래에 두고 `[BREAK]`로 말풍선을 나눈다.

```text
## messages
안녕![BREAK]오늘은 어땠어?
```

파서는 위 입력을 두 문자열로 바꾼다. `## messages`가 없으면 전체 텍스트를 같은 방식으로 파싱한다. 빈 본문은 무응답으로 완료할 수 있다. 원문·파싱된 말풍선·실제 전송은 [데이터와 대화](데이터와%20대화.md#생성-기록을-읽는-방법)에서 구분한다.

## 변경 후 언제 반영되는가

| 변경 | 적용 방식 |
| --- | --- |
| `logging.level` | YAML 재로딩 후 기존 로거에도 반영. |
| 전송 길이·Humanize 설정 | 전송에서 설정을 다시 읽는다. 진행 중인 조각 전체의 길이 한도는 전송 시작 때 고정한다. |
| 캐릭터 목록·연결·기본 선택, `bufferTimeout`, `responseMode`, Decision 설정 | 프로세스를 재시작한다. |
| 환경 변수·API 인증 | 프로세스를 재시작한다. |
| 프롬프트 팩·`sequence.js` | 변경 후 재시작해서 확인한다. 동적 import 캐시가 있다. |

YAML은 공통 watcher 하나로 읽고 캐릭터별 설정을 만든다. 재로딩 오류가 나면 해당 설정의 마지막 정상 값을 유지한다. 파일을 읽었다는 로그가 모든 객체의 재구성을 뜻하지는 않는다.
