# 플랫폼 독립 계약

공통 계약은 `src/application/contracts.js`의 JSDoc에 정의한다. 플랫폼 객체에서 필요한 데이터만 추출하고 전송 기능을 `ChannelPort`로 감싸면 같은 파이프라인을 사용할 수 있다.

| 계약 | 주요 필드와 의미 |
| --- | --- |
| `NormalizedMessage` | `platform`, `platformMessageId`, `platformChannelId`, nullable `platformServerId`, `editedAt`, `content`, `author` |
| `NormalizedAuthor` | `platformUserId`, `handle`, nullable `displayName`, `isBot` |
| `ChannelPort` | `platform`, `platformChannelId`, `send`, `sendTyping` |
| `OutgoingMessage` | 선택적 `content`, `files` |
| `MessageEvent` | `kind: CREATE/UPDATE/DELETE`, `channel`, `botId`, 메시지 또는 `loadMessage`, 삭제 ID 목록 |
| `ConversationRequest` | `channelPort`, `internalChannelId`, `botId`, 선택적 `turnId`, `rerollGenerationId` |

`ChannelPort.send`는 플랫폼 전송 완료 후 `NormalizedMessage`를 반환해야 한다. 이 반환값으로 Message와 SENT 사건을 저장한다. `sendTyping`도 비동기 계약이다.

부분 메시지의 `loadMessage`는 채널 수신 순서 큐 안에서 호출한다. 밖에서 먼저 조회하면 늦은 네트워크 응답 때문에 사건 순서가 바뀔 수 있다. DELETE는 본문 재조회 없이 플랫폼 ID 목록을 전달한다.

`editedAt`는 플랫폼의 수정 버전 정보이며 수정 순간을 목격했다는 증거가 아니다. 목격 여부는 세션과 사건 저장 정책이 결정한다. `turnId`는 메모리 안의 Symbol로, DB ID와 구분한다.

## 공개 진입점

메시지는 `messageHandler.handle`로 전달한다. 채널은 `activateChannel`·`channelCatalog`, 확인된 삭제는 `storedMessageService`, 생성 정보는 `getGenerationInfo`, 재생성은 `rerollConversation`을 사용한다. 계약이나 반환 형식을 바꾸면 두 플랫폼의 어댑터와 관련 테스트를 함께 확인한다.

## 이벤트별 필수 데이터

CREATE·UPDATE는 완전한 message 또는 비동기 loadMessage를 제공해야 한다. DELETE는 platformMessageIds 목록을 제공한다. 공통으로 channel과 botId가 필요하다. JSDoc 계약이 런타임 validation을 자동으로 생성하지 않으므로 잘못된 조합을 전달하면 실제 접근 단계에서 오류가 발생할 수 있다.

botId는 응답할 봇의 플랫폼 사용자 ID다. 내부 User ID나 character ID를 넣으면 자신의 출력 판별이 달라진다. ConversationRequest의 internalChannelId는 DB Channel.id이며 channelPort.platformChannelId와 다르다.

## 어댑터의 send 구현 조건

send는 플랫폼 API에 메시지를 전달하고, 성공이 확인된 반환 객체에서 플랫폼 message/channel/author ID를 추출한다. 입력 payload를 그대로 성공 반환값으로 돌려주면 실제 플랫폼 ID와 저장 Message가 불일치한다.

플랫폼 SDK의 부분 객체를 services에 넘기지 않고 조회 함수로 감싼다. 정규화 시 nullable 서버 ID와 editedAt의 의미를 유지한다. 현재 계약에 없는 첨부 데이터를 추가하려면 MessageService 저장 인자와 모델 렌더링 경로까지 함께 연결해야 한다.

## 유스케이스 결과를 읽는 방법

ActivateChannel.execute는 upsert한 DB 채널을 반환한다. ChannelCatalog의 화면용 id는 플랫폼 channel ID다. GetGenerationInfo.execute는 메시지를 찾지 못하면 null, 메시지는 있지만 생성 연결이 없으면 generation=null인 결과를 반환한다.

RerollConversation.prepare의 NOT_REROLLABLE·MESSAGES_NOT_FOUND·READY는 준비 단계의 결과이며 execute의 성공 여부와 구분한다. 삭제 서비스는 확인된 삭제 개수를 반환한다. 이런 차이를 플랫폼에서 임의로 같은 boolean으로 바꾸면 사용자 안내가 부정확해진다.
