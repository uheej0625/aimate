# 권한과 정책

Policy는 **어떤 플랫폼의 어떤 범위에서 특정 동작을 허용하는가**를 나타낸다. 대화 전용 설정이나 Discord 전용 테이블이 아니라 유형별 허용·거부 정책이다. 저장소와 판정기는 플랫폼 SDK에 의존하지 않는다.

현재 등록된 정책 유형은 `conversation` 하나다. Discord의 `/정책 설정 유형:대화`와 대화 수신·생성·전송에 연결되어 있다. `channel.create`, `profile.view` 등은 향후 확장 예시이며, 해당 유형의 명령·동작별 집행은 아직 구현하지 않았다. 기존 멤버 조회 도구에 별도의 프로필 조회 정책이 생겼다는 뜻은 아니다.

## 정책의 구성

| 필드 | 의미 |
| --- | --- |
| characterId | 정책을 소유하는 캐릭터 ID |
| platform | discord·cli 등 플랫폼 식별자 |
| type | 허용 여부를 판단할 동작 유형. 현재 conversation |
| scope·targetId | 정책을 적용할 범위 종류와 플랫폼 대상 식별자 |
| platformServerId | 서버별 조회용 식별자. 서버가 없는 환경에서는 null |
| effect | 기본 효과. allow는 허용, deny는 거부, null은 상속 |
| temporaryEffect·expiresAt | 기본 효과 위에 적용하는 임시 효과와 만료 시각 |
| updatedBy·updatedAt | 변경한 플랫폼 사용자 식별자와 변경 시각 |

`(characterId, platform, type, scope, targetId)`를 복합 기본 키로 사용한다. 같은 채널이어도 캐릭터나 유형이 다르면 별도 정책이다. 한 유형의 설정 변경·상속·만료가 다른 유형을 바꾸지 않는다. Server·Channel 등록 없이도 설정할 수 있다. 플랫폼 내 대상 ID의 고유성은 기존 Server·Channel 모델과 같은 전제를 사용한다.

정책은 현재 범위를 기준으로 서비스의 동작을 제어한다. 사용자·역할별 ACL이나 역할 정책 간 충돌 해결은 제공하지 않는다. 정책 명령을 실행하는 사람의 서버 관리 권한과 봇의 실제 Discord 권한은 별도로 확인한다. Policy의 allow는 Discord가 부여하지 않은 플랫폼 권한을 만들어 주지 않는다.

## 공통 판정

어댑터는 적용 가능한 범위를 우선순위 순서로 전달한다. 공통 판정기는 요청한 type과 같은 정책만 검사하며, 구체적인 범위 이름이나 Discord 계층을 가정하지 않는다. Discord는 채널 → 카테고리 → 서버 순서를 전달한다. 스레드의 부모 채널 해석도 Discord 어댑터의 책임이다.

각 범위에서 아직 만료되지 않은 임시 효과, 기본 효과 순서로 확인한다. 둘 다 없으면 다음 범위를 검사한다. 끝까지 유효한 정책이 없으면 기본 거부다. 다른 유형의 허용 정책은 현재 유형을 허용하는 근거가 될 수 없다.

PolicyRepository는 생성 시 characterId를 요구하며 모든 조회·변경·삭제에 같은 소유 범위를 적용한다. `PolicyRepository.list`는 플랫폼·정책 유형을 필수로 받아 해당 서버 또는 서버가 없는 문맥의 정책만 조회한다. `set`은 allow/deny만 저장하며 `remove`는 플랫폼·유형·범위·대상을 모두 요구한다. 따라서 유형을 빠뜨린 삭제로 다른 기능의 정책을 지울 수 없다. `resolvePolicy`도 요청 유형을 재검사한다.

현재 Discord 어댑터는 `PolicyType`에 등록된 유형만 설정·조회·집행한다. 아직 등록되지 않은 유형의 허용 요청은 거부한다. 저장 계층이 문자열 유형을 저장할 수 있다는 사실과 기능이 구현되었다는 사실은 구분한다.

## 임시 효과

임시 효과를 설정하면 기본 효과를 보존한다. 같은 대상·유형에 다시 설정하면 임시 효과와 만료 시각을 교체한다. 무기한 설정은 기본 효과를 바꾸고 임시 효과를 지운다. 상속은 해당 유형·대상의 행을 삭제한다.

만료 시각부터 임시 효과를 무시하고 그 시점의 기본·상위 정책으로 다시 판정한다. 이전 상태를 복사하거나 반대 효과로 뒤집지 않는다. 판정은 DB를 수정하지 않으며 만료된 임시 값만 남은 행은 유효 정책 목록에서 제외한다. 재시작해도 저장된 만료 시각을 사용한다.

## 대화 유형의 집행

DiscordPolicyService가 conversation 유형의 `isAllowed`를 제공한다. 조립부는 이를 공통 대화 계층의 `isEnabled(ChannelPort)` 계약으로 감싼다. MessageHandler와 ChatFlow가 같은 검사를 사용하며 메시지 전송·도구 실행에는 `delivery.canDeliver`를 전달한다.

대화 거부 시 새 입력을 저장하지 않고 대기·진행 중인 대화를 중단한다. 기존 메시지의 수정·삭제와 이미 확인된 외부 작업의 결과 저장은 유지한다. 구체적인 중단·스레드·로그 채널·시간 제한과 명령 계약은 [Discord 정책](../플랫폼/Discord%20정책.md)에 있다. CLI는 채널 생성 시 캐릭터별 conversation/channel allow 정책을 저장한다. 채널 목록·입력·전송은 이 권한으로 제한하며 다른 캐릭터의 로컬 채널을 자동 열람하지 않는다. 연결별 정책 판정은 Host의 플랫폼 라우터가 선택한다.

## 새 유형을 추가할 때

새 동작은 PolicyType에 유형을 등록하고, 실행에 맞는 범위 체인과 실제 권한 검사를 정한 뒤 **외부 작업을 시작하기 전에 해당 유형의 정책을 집행**해야 한다. 그 후 명령의 유형 선택과 상태 표시를 추가한다. 데이터 모델·저장소·상속·임시 효과 처리는 재사용한다. 등록만 하고 실제 실행 경로에서 검사하지 않은 기능을 권한 제어가 구현된 것으로 설명하지 않는다.
