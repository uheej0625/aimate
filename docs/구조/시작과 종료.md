# 시작과 종료

## 시작 순서

Discord와 CLI 진입점은 Windows 인코딩 보정과 `.env` 로드를 수행하고 `createCharacterConfigManager`로 선택한 캐릭터의 독립 설정을 만든다. 로거는 같은 설정의 공통 app·logging 값을 사용한다. 현재 두 진입점은 각각 한 캐릭터를 실행하며 목록 전체를 동시에 기동하지 않는다.

Discord는 선택한 캐릭터에 Discord 연결이 있는지 확인하고 `createDiscordApplication`을 호출한다. container는 환경 변수에서 별도 AI 인증 스냅샷을 만들고 chat·image 설정과 함께 검증한다. 인증 정보는 일반 설정에 합치지 않고 생성기에 전달한다. 캐릭터 `config.json`의 필수 timezone을 검증하고 도구를 로드한 뒤 이벤트·명령을 연결한다. 종료 핸들러 등록 후 캐릭터별 토큰으로 로그인하고 `app.initializeAccount()`를 기다린다. 실제 Discord 사용자 ID로 계정 소유권을 확인하며 준비가 끝나기 전 메시지·명령 이벤트는 처리하지 않는다. ready 이벤트는 접속 로그만 기록한다. 소유권 충돌은 ConfigurationError로 main까지 전달되어 기동에 실패한다.

CLI는 CLI 연결이 있는지 확인하고 `cli-bot-<characterId>` 모의 계정과 같은 container를 사용한다. 종료 핸들러와 캐릭터 소유 계정을 준비하고 `startRepl`로 TUI를 연다. 여기서 모의인 것은 플랫폼 client이며 AI 생성은 실제 호출이다.

## 종료 순서

`SIGINT`와 `SIGTERM`에서 중복 종료를 막고 다음 작업을 수행한다.

1. 버퍼 타이머와 세션 상태 정리, Discord 대화 정책 재확인 타이머 종료와 실행 중 재확인 작업 대기.
2. 진행 중인 모델 요청에 abort 전달.
3. `PROCESSING`·`GENERATED` Generation을 `CANCELLED`로 변경.
4. Discord client 종료, 설정 watcher 종료, Prisma 연결 종료.
5. 종료 코드 0으로 종료.

GenerationRepository와 DB disconnect 함수는 종료 핸들러에 주입된다. 강제 종료로 이 절차가 실행되지 않으면 진행 상태가 남을 수 있다. 별도 자동 복구 worker는 현재 조립되어 있지 않다.

## 설정 변경의 적용 범위

ConfigManager는 YAML 변경을 감시하지만 모든 객체를 다시 만들지는 않는다. 버퍼 시간·캐릭터 경로·Repository의 캐릭터 ID처럼 생성자에서 고정한 값은 재시작해야 확실히 적용된다. `sequence.js`는 동적 import 캐시의 영향도 받는다.

파일 reload는 YAML을 다시 읽고 Vertex 프로젝트·리전의 일반 설정 환경 변수 override를 재적용한 뒤 변경 알림을 보낸다. 별도로 읽은 AI 인증 스냅샷은 그대로 유지하고 변경 알림에 포함하지 않는다. `.env` 파일 자체는 다시 읽지 않으므로 `.env` 인증 값·캐릭터·팩 변경 후에는 재시작하는 운영 방식을 사용한다.

## 기동 책임을 가진 구성 요소

| 구성 요소 | 책임 | 실패가 드러나는 위치 |
| --- | --- | --- |
| loadEnv | dotenv 로드. 기본적으로 기존 shell 환경 변수를 덮어쓰지 않음 | 환경 설정 단계 |
| createConfigManager | YAML 일반 설정 로드와 Vertex 프로젝트·리전 override 적용 | 설정 검증 또는 이후 값 사용 |
| loadAiCredentials | 환경 변수에서 별도 AI 인증 스냅샷 생성 | provider 인증 검증 또는 실제 요청 |
| createContainer | 인증 스냅샷 생성·설정 검증과 공통 의존성 생성 | 플랫폼 main 초기화 |
| createDiscordApplication | 공통 객체와 Discord 이벤트·명령 연결 | Discord 기동 |
| createCharacterConfigManager | 캐릭터 목록·연결 검증, 유효 설정 병합과 런타임 ID 고정 | 진입점 설정 준비 |
| BotAccountService.initBotAccount | 캐릭터 User 재사용·계정 연결·소유권 충돌 거부 | Discord 로그인 직후 또는 CLI 준비 |
| registerShutdown | 종료 신호 연결과 정리 절차 | 종료 로그 |

Discord는 main의 ConfigurationError를 코드 78로 분류한다. CLI 진입점에 동일한 오류 분류용 catch가 모두 구현되어 있다고 가정하지 않는다. 플랫폼별 기동 오류 설명을 추가할 때 실제 진입점에서 잡는 범위를 확인한다.

## 종료할 때 작업을 기다리는가

registerShutdown은 버퍼를 없애고 요청에 abort를 전달하지만 모든 ChatFlow Promise가 끝날 때까지 join하지 않는다. 이후 DB 진행 상태를 취소하고 플랫폼·설정·DB 연결을 닫는다. 따라서 ‘graceful’은 정리 순서를 가진 종료이며 진행 중인 응답을 모두 완성해 주는 정책이 아니다.

generation 취소·client 종료·DB disconnect의 일부 오류는 로그를 남기고 다음 정리로 진행한다. DB 취소 실패가 있으면 종료 코드만 보고 모든 row가 정리되었다고 판단하지 않는다. 강제 종료와 프로세스 손실은 이 신호 핸들러의 보장 밖이다.
