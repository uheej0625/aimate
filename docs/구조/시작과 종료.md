# 시작과 종료

## 공통 실행부

Discord와 CLI 진입점은 `src/main.js`의 main을 호출한다. Windows 인코딩 보정과 .env 로드 후 공통 ConfigManager·로거·DB 연결을 준비하고 캐릭터 목록으로 Host를 만든다. 한 프로세스의 공통 DB는 Host만 닫는다.

- `npm start`와 `npm run discord`: Discord 연결이 있는 모든 캐릭터를 한 프로세스에서 실행한다.
- `npm start -- --character alice`: 지정한 캐릭터만 실행한다.
- `npm run cli -- --character alice`: 해당 캐릭터의 CLI와 설정된 Discord 연결을 같은 런타임에서 실행한다. 생략 시 YAML의 character가 CLI 기본 선택이다.
- `npm run deploy`: 목록의 모든 Discord 계정에 명령을 배포한다. `-- --character alice`로 제한할 수 있다.

각 캐릭터는 독립 ConfigManager·세션·버퍼·EventBus·abort registry·캐릭터 범위 Repository를 가진다. 같은 캐릭터의 플랫폼 연결은 이 런타임을 공유한다. ID와 계정 목록 변경은 재시작으로 적용한다. 한 프로세스에서 같은 characterId의 활성 런타임을 중복 생성하지 않는다.

## 기동 순서와 부분 실패

1. 공통 설정과 DB 연결을 준비한다. 공통 준비 실패는 전체 실패다.
2. 캐릭터별 설정과 필수 시간대, AI 일반 설정·별도 인증 객체를 검증하고 서비스를 조립한다.
3. 연결별 이벤트·명령을 연결하되 입력은 닫아 둔다. 플랫폼 인증 후 실제 자기 계정을 같은 캐릭터 User에 연결한다.
4. 모든 연결의 계정 준비 시도가 끝난 뒤 성공한 연결의 입력·정책 타이머·로그를 활성화한다. 다른 캐릭터 계정이 외부 사용자로 먼저 저장되는 일을 피한다.

연결 실패는 `connection.start.failed`, 캐릭터 조립 실패는 `character.start.failed`로 기록하고 다른 연결은 유지한다. 성공한 연결이 하나도 없으면 공통 자원까지 정리하고 실패한다. ConfigurationError는 코드 78, 나머지 기동 오류는 1이다. Host 시작 로그에는 런타임 수·활성 연결 수·실패 수가 남는다.

Discord client는 연결별 팩터리로 생성한다. 입력 활성화는 로그인과 실제 계정 초기화 이후다. 연결이 준비되지 않은 동안 입력과 새 도구 작업을 시작하지 않는다. CLI는 캐릭터별 `cli-bot-<id>` 계정을 준비한 뒤 TUI를 연다. CLI 플랫폼만 모의이며 AI 생성은 실제 호출이다.

## 종료와 격리

SIGINT·SIGTERM은 공통 실행부에 한 번 등록한다. 중복 신호는 같은 종료 작업을 기다린다.

1. 모든 연결의 입력을 막고 정책 타이머·CLI 화면을 닫는다.
2. 각 캐릭터의 버퍼·세션을 정리하고 자기 모델 요청에 abort를 전달한다.
3. 수신·명령 작업, ChatFlow, 세션 큐를 캐릭터마다 최대 5초 기다린다. 취소를 무시하는 외부 작업을 무기한 기다리지 않는다.
4. 해당 캐릭터의 진행 Generation을 취소하고 로그 편집을 정리한 뒤 플랫폼 연결과 설정 watcher를 닫는다.
5. 공통 DB를 마지막에 한 번 닫는다.

Host.closeCharacter는 한 캐릭터만 종료하고 다른 캐릭터나 공통 DB를 닫지 않는다. Host.closeConnection은 해당 연결 입력과 그 플랫폼 대화만 중단한다. 캐릭터와 연결 종료 함수는 process.exit를 호출하지 않는다. 일부 정리 오류는 로그에 남기고 다른 자원 정리를 계속한다. 프로세스 강제 종료·이벤트 루프 장애와 취소를 무시하는 외부 API를 프로세스 분리 수준으로 격리하지는 않는다.

## 설정 reload

공통 logging 수준과 각 캐릭터의 유효 일반 설정은 YAML watcher로 다시 읽는다. 캐릭터 ID·연결 목록·인증 스냅샷·생성자에서 고정한 버퍼 시간·캐릭터 경로는 재시작해야 한다. .env 자체를 다시 읽거나 런타임을 자동 재조립하지 않는다. `sequence.js`는 import 캐시의 영향도 받는다.
