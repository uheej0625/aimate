## 테스트 실행

```powershell
# 전체 테스트
npm test

# 변경한 기능만 빠르게 확인
node --test test/messages/MessageSplitter.test.js
node --test test/chat/ChatFlow.test.js

# 메시지 저장부터 생성·전송까지 확인
node --test test/integration/ChatPipeline.integration.test.js
```

Node.js 기본 test runner를 사용한다. 테스트 모델·연결은 대체 구현을 사용하며 통합 테스트는 `test/.tmp/`에 임시 SQLite DB를 만든다. AI 키나 실제 Discord 로그인이 없어도 테스트할 수 있다. Prisma Client를 아직 생성하지 않았다면 `npm run db:generate`를 먼저 실행한다.

단위 테스트는 해당 기능의 규칙을, 통합 테스트는 실제 Repository·서비스를 연결한 결과를 확인한다. 실제 모델의 대화 품질과 Discord 인증·서버 권한은 별도로 실행해 확인한다.

## 도구 하나 추가하기

1. [getTime.js](../src/tools/definitions/getTime.js)처럼 `src/tools/definitions/<이름>.js`에 default export를 만든다. `name`, `description`, `inputSchema`, `execute`가 필요하다.
2. `platforms`, `requires`, `channelCapabilities`, `targetPlatform`으로 사용 조건을 정한다. `ToolRegistry`가 폴더를 읽어 자동 등록한다.
3. 새 의존성이 필요하면 [container.js](../src/core/container.js)에서 조립하고 [ToolExecutionContextFactory.js](../src/tools/ToolExecutionContextFactory.js)를 통해 전달한다.
4. `test/tools/`에 입력·실행 결과·취소를 확인하는 테스트를 추가한다. 외부 작업은 테스트에서 대체한다.

`channelCapabilities`는 입력 채널의 `reply`, `react` 같은 기능을 요구한다. `targetPlatform: "discord"`는 입력 플랫폼과 별개로 같은 캐릭터의 Discord 연결을 사용한다. 이미지 도구는 첨부 미지원 채널에 제공되지 않는다. 실행 직전에도 연결·정책·취소를 다시 확인한다.

## 플랫폼 하나 추가하기

플랫폼 구현은 다음 경계를 채운다.

| 구현할 부분 | 기존 예시 |
| --- | --- |
| 수신 데이터를 MessageEvent로 정규화 | [Discord adapter.js](../src/platforms/discord/adapter.js), [CLI adapter.js](../src/platforms/cli/adapter.js) |
| 전송과 조회를 제공하는 ChannelPort | 같은 adapter와 [contracts.js](../src/application/contracts.js) |
| 계정 준비·입력 활성화·정책·종료 | [createDiscordApplication.js](../src/platforms/discord/createDiscordApplication.js), [CLI connection.js](../src/platforms/cli/connection.js) |
| 설정 검증과 실행 연결 | [characters.js](../src/config/characters.js), [main.js](../src/main.js) |

공통 대화 코드에는 정규화 데이터와 port를 전달한다. 플랫폼 이벤트는 공통 Handler로, 사용자 명령은 애플리케이션 유스케이스로 연결한다. 새 서비스를 도입할 때는 container에서 의존성을 조립한다.

## 대화 변경에서 지켜야 할 기준

- 메시지의 최신 상태와 캐릭터별 관찰을 구분한다. 이미 읽은 본문을 최신 DB 값으로 덮어 설명하지 않는다.
- 새 입력으로 현재 turn이 바뀌면 이전 생성이 뒤늦게 완료되거나 추가 전송하지 않게 한다.
- 이미 전송을 확인한 결과는 취소 뒤에도 저장한다. 저장 실패 재시도에서 플랫폼 전송을 반복하지 않는다.
- 입력은 모델 호출 전에 고정하고, 정상 완료와 처리 cursor를 함께 반영한다. 무응답도 완료할 수 있다.
- 캐릭터별 정책·계정·생성·관찰 범위를 유지한다.

이 기준을 바꾸는 작업은 [대화 통합 테스트](../test/integration/ChatPipeline.integration.test.js)에 재현 사례를 추가해 확인한다. 상세 의미는 [데이터와 대화](데이터와%20대화.md)에 있다.

## 변경을 마칠 때

변경한 기능의 테스트를 실행하고, 저장·생성·전송 경계를 바꿨다면 통합 테스트도 실행한다. 프롬프트 변경은 같은 대화 사례로 실제 출력까지 확인한다. DB 변경은 개발 환경에서 `npm run db:init`으로 현재 스키마를 적용한다. 이 프로젝트는 후방 호환 계층과 데이터 마이그레이션을 유지하지 않는다.

동작·계약·설정을 바꿨으면 해당 주제의 위키를 함께 고친다. 새 파일은 코드 지도에 역할을 기록한다. 설명은 현재 동작과 필요한 근거에 집중하고, 미구현 제안은 현재 기능과 구분한다. 인증 값·비공개 프롬프트·캐릭터 원문은 문서에 넣지 않는다.
