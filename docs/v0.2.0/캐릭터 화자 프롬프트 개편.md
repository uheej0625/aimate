# 캐릭터 화자 프롬프트 개편

이 문서는 `content/prompts/ultimate/chat`의 자연어 프롬프트를 개편하는 방향을 정리한다. [컨텍스트 구성 개편](./컨텍스트%20구성%20개편.md)을 바탕으로 구현된 현재 `sequence.js`, `HistoryService`, `SequenceBuilder`의 배치와 사건 기록 형식을 유지한다.

이 문서의 핵심은 AI의 정체를 부정하거나 AI가 사람이 되었다고 선언하는 것이 아니다. 모델은 그대로 두고, 대화에서 출력될 말의 화자를 캐릭터로 명확히 지정한다. 이른바 연기 지시는 출력 형식, 도구 호출, 입력 데이터 해석처럼 실행에 필요한 운영 규칙에만 얇게 사용한다.

이 문서는 설계안이다. 실제 프롬프트, 조립 코드, 캐릭터 콘텐츠는 변경하지 않는다.

## 범위와 전제

- 이번 개편은 화자 정의, 공통 행동·말투 규칙, 운영 지시의 문구와 중복을 정리한다. 컨텍스트를 다시 설계하거나 DB 스키마를 변경하지 않는다.
- 현재의 고정 지시 → 이전 기록 → 응답 지시·현재 시각 → 마지막 봇 발언 이후 관찰 순서를 유지한다. 각 메시지의 역할과 사건 경계도 유지한다.
- `channelMessageNo`, `inputMessageNos`, 구조화된 `request_context`는 도입하지 않는다. 번호와 `reply`·`react` 도구는 [별도 설계](./channelMessageNo와%20reply-react%20도구.md)이며 이번 개편의 선행 조건이 아니다.
- 기존 가시성 정책 안에서 전체 사건을 포함하는 동작과 `summary`·`fact`·`episode`의 미구현 상태를 유지한다.
- 관찰 시각의 오전·오후 표시는 합의한 `AM/PM`을 사용한다. 이를 `오전/오후`로 바꾸기 위한 변환 코드나 의존성은 추가하지 않는다. 현재 시각의 ISO 8601 형식은 유지한다.

## 개편 목표

- 캐릭터를 흉내 내는 외부 연기자 대신, 대화의 발화 주체로 정의한다.
- 이름, 존재 형태, 성격, 말투, 지식, 관계는 캐릭터 설정이 결정하게 한다.
- 공통 프롬프트가 모든 캐릭터에 같은 감정선이나 인간성을 덧씌우지 않게 한다.
- 출력 형식과 도구 사용처럼 런타임이 요구하는 계약은 캐릭터 설정과 분리한다.
- 실제 발언·관찰 사건과 응답 지시·현재 시각을 구분해서 해석하게 한다.
- 각 규칙의 소유 파일을 하나로 정해 중복 지시와 충돌을 줄인다.

## 기본 관점

모델, 화자, 캐릭터 설정은 다음 관계로 다룬다.

```text
모델
└─ 주어진 입력으로 다음 응답을 생성한다.
   └─ 대화에서 말하는 화자 = Character Identity에 정의된 캐릭터
      ├─ 정체성·성격·지식·한계·관계: 캐릭터 설정이 결정
      ├─ 현재 반응: 설정 + 관찰한 사건 + 현재 요청이 결정
      └─ 출력·도구 호출 방식: 공통 운영 규칙이 결정
```

따라서 공통 프롬프트에서는 다음과 같은 존재론적 선언을 피한다.

- “너는 AI가 아니다.”
- “실제로 살아 있는 사람이다.”
- “캐릭터와 완전히 하나가 되어라.”
- “Method Actor처럼 내면에서 연기하라.”

이런 선언은 캐릭터가 인간이라는 전제를 강요하며, AI나 봇이라는 정체성을 가진 캐릭터와 충돌한다. 필요한 지시는 “이 대화의 화자는 제공된 캐릭터다” 정도면 충분하다.

## 현재 프롬프트의 주요 문제

### 화자 정의가 서로 충돌한다

`system.md`는 모델에게 캐릭터를 연기하라고 지시하지만, `persona-frame.md`는 모델 자신이 곧 캐릭터라고 선언한다. 여기에 `Ghost in the Messenger`, `Method Actor` 같은 비유가 추가되어 실제로 필요한 화자 지정보다 지시가 커졌다.

### 공통 규칙이 캐릭터의 성격을 덮어쓴다

`behavior-core.md`는 경계심, 취약함 회피, 긴장, 갑작스러운 솔직함 등을 일반적인 사람다움으로 제시한다. 그러나 이런 특징은 특정 캐릭터의 성격이어야 한다. `assistant-like helpfulness`를 넓게 금지하는 규칙도 도움을 잘 주거나 상담을 잘하는 캐릭터와 충돌할 수 있다.

### 메신저 리듬이 고정되어 있다

`messenger-style.md`의 “2~4개 메시지”, “각 1~2문장”은 간단한 반응도 여러 조각으로 늘리고, 설명이 필요한 답은 지나치게 압축할 수 있다. `ㅋㅋ`, 머뭇거림, 불완전한 문장을 사람다움의 증거처럼 반복할 위험도 있다.

### 같은 계약이 여러 파일에 반복된다

출력 형식, 언어, 캐릭터 유지, 사용자 상태 추정 금지가 `system.md`, `messenger-style.md`, `response-contract.md`, `final-check.md`에 중복되어 있다. 규칙을 고칠 때 일부 파일만 달라지면 서로 충돌한다.

### 기억과 입력 설명이 현재 조립 구조와 맞지 않는다

`memory.md`와 `user-action.md`는 이미 활성 시퀀스에서 제외되어 있다. 하지만 `system.md` 등에는 별도 기억 계층이 제공된다는 설명이 남아 있다. 현재 입력은 마지막 봇 전송까지의 기록, 응답 지시·현재 시각, 이후 관찰로 구성되므로 실제로 제공되는 정보에 맞춰 설명을 정리해야 한다. 미사용 파일의 `<Recent>`, `<This_Moment>`, `<User_Action>` 구간을 다시 도입하지 않는다.

## 규칙의 소유권

한 규칙은 가능한 한 한 파일만 소유한다.

| 규칙 | 소유 파일 |
| --- | --- |
| 화자가 누구인지 | `persona-frame.md` |
| 캐릭터의 구체적인 정체성·성격·말투·관계 | `state.md`가 주입하는 캐릭터 `identity.md` |
| 관찰과 추측의 구분, 관계의 연속성 | `behavior-core.md` |
| 채팅에서 문장을 나누는 방식 | `messenger-style.md` |
| 최종 텍스트의 파싱 형식 | `response-contract.md` |
| 도구 선택과 호출 단계의 처리 | `system.md`, 필요한 호출 형식은 API의 도구 정의 |
| 사건 기록과 응답 지시·현재 시각의 구분, 기본 응답 언어 | `system.md`의 짧은 운영 규칙 |
| 파일의 책임과 실제 적용 순서 | `README.md`, `sequence.js` |

캐릭터마다 달라질 수 있는 규칙은 공통 프롬프트에 두지 않는다. 예를 들어 친절함, 장난기, 감정 표현 정도, 존댓말, 이모티콘, 지식 수준, 인간 또는 AI라는 존재 형태는 캐릭터 설정의 책임이다.

## 모델 입력 적용 순서

현재 조립 순서를 유지한다. 도구 정의는 문자열 메시지 사이에 넣지 않고 API의 `tools`로 별도 전달한다.

| 순서 | 입력 | 역할 | 성격 |
| --- | --- | --- | --- |
| 1 | `system.md` | API `system` | 화자 연결과 운영 계약 |
| 2 | `persona-frame.md` | 고정 `user` | 캐릭터가 대화의 화자라는 정의 |
| 3 | `state.md` | 고정 `user` | 렌더링된 캐릭터 정체성 |
| 4 | `behavior-core.md` | 고정 `user` | 관찰 범위와 관계의 연속성 |
| 5 | `messenger-style.md` | 고정 `user` | 메신저 표현 방식 |
| 6 | `summary` 자리 | 향후 컨텍스트 | 현재는 주석만 있으며 주입하지 않음 |
| 7 | 마지막 봇 전송 사건까지의 메시지·관찰 사건 (`history`) | 기존 `user` / `assistant` 역할 | 관찰 순서가 유지되는 누적 기록 |
| 8 | `fact` 자리 | 향후 가변 컨텍스트 | 현재는 주입하지 않음 |
| 9 | `episode` 자리 | 향후 가변 컨텍스트 | 현재는 주입하지 않음 |
| 10 | `response-contract.md` + `final-check.md` + `## Current Time` (`response`) | 하나의 요청별 `user` 메시지 | 출력 규칙과 이번 생성의 기준 시각 |
| 11 | 마지막 봇 전송 이후의 모든 관찰 (`pending`) | 기존 `user` / `assistant` 역할 | 발언·수정·삭제·뒤늦게 읽은 과거 내역 |

`response-contract.md`와 `final-check.md`는 `SequenceBuilder`의 `response` 단계에서 현재 시각과 합쳐진다. 이번 개편에서는 두 파일을 고정 구간으로 옮기거나 별도 메시지로 나누지 않는다. `final-check.md`는 중복을 줄이되 유지하며, 제거 여부는 별도 변경에서 판단한다.

`history`와 `pending`의 경계는 현재 캐릭터가 현재 채널에 마지막으로 전송한 `SENT` 사건이다. 처리 완료 커서와는 다르며, `pending`은 처리 대상 입력만이 아니라 마지막 봇 전송 이후의 모든 관찰을 포함한다. 봇 전송이 없으면 전체 관찰이 `pending`에 있고, 이후 관찰이 없으면 마지막 구간은 비어 있다. 다음 봇 전송 후 기존 관찰이 `history`로 이동해도 사건의 본문·역할·순서·시각 표시는 유지한다.

입력 형태는 다음과 같다. 미구현 자리는 실제 메시지를 만들지 않는다.

```text
system.md
→ persona-frame.md
→ state.md
→ behavior-core.md
→ messenger-style.md
→ summary(미구현)
→ 마지막 봇 전송까지의 전체 기록(history)
→ fact(미구현)
→ episode(미구현)
→ response-contract.md + final-check.md + 현재 시각(response)
→ 마지막 봇 전송 이후 관찰(pending)
```

## 파일별 개편 방향

### `system.md`

화자의 성격을 만들지 않고 런타임에 필요한 계약만 둔다.

포함할 내용:

- 대화에서 출력되는 발화의 화자는 제공된 캐릭터라는 연결
- 실제 사용자 발언, 관찰 사건, 응답 지시·현재 시각의 구분
- 텍스트를 반환할 때 출력 계약을 따르는 규칙
- 도구가 필요한 작업은 제공된 도구로 수행하고 결과를 확인하는 규칙
- 기본 응답 언어와 사용자가 명확히 다른 언어를 쓴 경우의 처리

제외할 내용:

- AI 정체성 부정
- 인간처럼 살아 있다는 선언
- 자연스러운 사람처럼 보이기 위한 감정 연출
- 특정 캐릭터의 친절함, 거리감, 주도성
- 도구를 “특별하게 느껴질 만큼 드물게” 쓰라는 감성적 기준

도구는 필요성과 기능을 기준으로 선택한다. 실행하지 않은 행동을 했다고 말하지 않고, 실패한 도구 결과를 성공으로 표현하지 않는 것이 핵심이다.

### `persona-frame.md`

비유를 제거하고 화자를 직접 정의한다.

권장하는 의미는 다음 정도다.

> 이 대화에서 말하는 화자는 아래 정체성에 정의된 캐릭터다. 응답은 그 캐릭터의 관점, 지식, 관계, 말투에서 나온다. 모델 자체에 관한 일반적인 가정으로 캐릭터의 정체성을 덮어쓰지 않는다.

`Heartbeat`, `Ghost in the Messenger`, `Method Actor`는 삭제한다. 감정의 복잡성이나 독립성은 공통 비유가 아니라 캐릭터 설정과 누적된 관계에서 나오게 한다.

### `state.md`

캐릭터 정체성만 주입한다.

```text
<Character_Identity>
{{character.identity}}
</Character_Identity>
```

현재 파일은 이미 캐릭터 정체성만 주입하므로 이 구성을 유지한다. 현재 시각은 `response` 단계의 `## Current Time`으로 전달한다. 나이와 학년처럼 날짜에 따라 계산되는 정체성 값은 캐릭터 정체성 렌더링 결과에 둘 수 있지만, 매 요청의 현재 시각 문자열을 정체성 안에 섞지는 않는다.

### `behavior-core.md`

캐릭터에 공통으로 적용할 수 있는 인식과 연속성 규칙만 남긴다.

남길 내용:

- 말, 사건 시각, 수정·삭제 관찰, 첨부 자료, 도구 결과처럼 제공된 정보만 관찰 사실로 취급한다.
- 상대의 숨은 생각과 의도는 추측할 수 있지만 사실로 확정하지 않는다.
- 기존 관계는 캐릭터 설정과 실제 누적 기록에서 이어진다.
- 한 번의 발언이 관계 전체를 즉시 뒤집지 않는다.
- 과거를 기억한다는 사실을 증명하려고 관련 없는 내용을 반복하지 않는다.
- 현재 반응은 캐릭터 설정만이 아니라 지금까지의 구체적인 교환에도 근거한다.

제거하거나 캐릭터 설정으로 옮길 내용:

- 취약함을 피한다는 전제
- 신뢰·친밀감·긴장을 반드시 세 축으로 추적하는 규칙
- 몸이나 기분이 설명보다 먼저 움직인다는 묘사
- 항상 불완전하고 복합적으로 보여야 한다는 요구
- 도움을 주는 말투 자체를 피하는 규칙
- 특별하거나 극적인 답을 만들기 위한 규칙

평범한 순간에는 평범하고 짧은 반응이 자연스러울 수 있다. 캐릭터다운 구체성은 매번 눈에 띄는 특이성을 추가하는 것이 아니라, 상황에 맞는 선택을 유지하는 데서 나온다.

### `messenger-style.md`

대화 채널의 표현 제약만 다루고, 실제 말투는 캐릭터 설정에 맡긴다.

권장 규칙:

- 짧은 반응은 한 메시지로 끝낼 수 있다.
- 화제 전환이나 호흡 분리가 자연스러울 때만 메시지를 나눈다.
- 길이는 현재 내용에 필요한 만큼 사용하되 메신저에서 읽기 어려운 장문은 피한다.
- 존댓말, 반말, 웃음 표현, 문장 완결성, 이모티콘은 캐릭터와 관계를 따른다.
- 행동 지문이나 서술자 문장을 채팅 본문에 넣지 않는다.
- 이미지 전송이나 상태 변경처럼 실제 동작이 필요한 경우 해당 도구를 사용한다.

고정된 “2~4개”, “각 1~2문장” 규칙은 제거한다. `[BREAK]`의 정확한 문법은 `response-contract.md`만 소유한다.

### `response-contract.md`

기존 출력 계약을 유지하고 자연스러움이나 캐릭터성은 여기서 다루지 않는다. `AIResponseParser`는 `## messages` 본문을 추출해 `[BREAK]`로 나누며, 한 줄·Markdown 제한은 프롬프트의 출력 규칙이다. 이를 강제하기 위해 파서를 변경하지 않는다.

유지할 계약:

```markdown
# response

## messages

첫 번째 메시지 [BREAK] 두 번째 메시지
```

- `## messages`의 본문은 한 줄이다.
- 여러 플랫폼 메시지가 필요할 때만 정확히 `[BREAK]`로 나눈다.
- 메시지 본문 안에는 제목, 목록, 코드 블록 등 파서와 충돌하는 Markdown을 넣지 않는다.
- 도구 호출 단계에서는 Markdown 응답을 함께 만들지 않는다.
- 도구 실행 뒤 최종 텍스트 응답이 필요한 단계에서는 다시 이 계약을 따른다.

예시에 메시지 세 개를 고정해서 보여주면 세 조각 출력을 유도할 수 있으므로 한 개와 선택적인 두 번째 메시지만 보여주는 편이 낫다.

### `final-check.md`

현재 `response` 단계의 소스로 유지하되, 사람처럼 행동하라는 지시와 감정·말투·언어 규칙의 중복을 제거한다. 이 파일이 새로운 규칙을 소유하지 않게 한다.

기존 규칙을 참조하는 다음 세 항목만 확인한다.

- 최종 텍스트가 `response-contract.md`와 일치하는가.
- `behavior-core.md`의 관찰 범위를 지켰는가.
- `system.md`에 따라 응답 지시와 현재 시각을 실제 발언과 구분했는가.

캐릭터성, 언어, 메신저 리듬은 각각의 소유 파일에서만 정의한다.

### `memory.md`

이미 활성 시퀀스에서 제외되어 있으므로 다시 주입하지 않는다. `<Foundation>`, `<Deep_Memory>`, `<Recent>` 블록과 기억 우선순위는 현재 사건 기록 구조와 맞지 않는다.

향후 `fact`와 `episode`가 구현되기 전에는 대체 파일이나 빈 블록을 만들지 않는다. 현재 `MemoryService`의 결과를 `fact` 또는 `episode`로 이름만 바꾸어 주입하지도 않는다. “과거를 과시하지 말고 현재 반응에 반영한다”는 일반 규칙만 `behavior-core.md`로 옮긴다.

### `user-action.md`

이미 활성 시퀀스에서 제외되어 있으므로 다시 주입하지 않는다. 최신 사용자 입력은 `pending`의 관찰 사건으로 한 번만 전달한다.

1인칭이 발언자를 가리킨다는 규칙과 응답 지시·현재 시각이 실제 발언이 아니라는 규칙은 `system.md`의 입력 해석 규칙으로 정리한다. 별도 입력 블록에 발언 본문을 복사하지 않는다.

### `sequence.js`

현재 시퀀스를 유지하며 이번 문구 개편을 위해 변경하지 않는다.

유지할 요소:

- 고정 지시 → `history` → `response` → `pending` 순서
- `response`의 `sources: ["response-contract.md", "final-check.md"]`와 조립 코드가 덧붙이는 현재 시각
- `summary`·`fact`·`episode`의 주석 자리와 주입하지 않는 상태
- 조회 개수나 `slice`로 사건을 자르지 않는 기본 조립 경로
- `memory.md`, `user-action.md`, 이동식 구간 태그, `cache-point`가 없는 활성 시퀀스

`HistoryService`의 사건 정렬과 마지막 봇 전송 기준 분할, `ChatContextPreparer`와 `SequenceBuilder`의 요청당 렌더링 시각 공유는 현재 구현을 사용한다. 새로운 시퀀스 단계나 번호 기반 입력 선택 기능을 추가하지 않는다.

### `README.md`

개편 후 실제 책임과 순서를 기록한다. 과거 설계 출처에 대한 설명보다 현재 계약을 우선한다.

다음 원칙을 명시한다.

- 캐릭터마다 달라지는 내용은 캐릭터 `identity.md`에 둔다.
- 관찰과 관계의 일반 규칙은 `behavior-core.md`에 둔다.
- 메신저 표현은 `messenger-style.md`에 둔다.
- 파싱 형식은 `response-contract.md`에만 둔다.
- 도구와 응답 지시·현재 시각의 해석은 `system.md`에 둔다.
- `final-check.md`는 `response` 단계에서 사용하는 최소 점검 파일로 기록한다.
- 사용하지 않는 `memory.md`, `user-action.md`는 활성 파일처럼 문서화하지 않는다.

### `image/photo.md`, `image/selfie.md`, `image/screenshot.md`

채팅 프롬프트의 화자 정의와 분리해서 유지한다. 이 파일들은 이미지 모델의 작업 지시이므로 장면, 외형 참조, 구도, 시간, 렌더링 제한을 명시하는 현재 역할이 적절하다.

다만 채팅 모델이 이미지 도구에 넘기는 인수는 캐릭터의 관점과 현재 대화에 맞아야 한다. 이미지 프롬프트 자체에 “사람처럼 행동하라” 같은 화자 연기 규칙을 추가하지 않는다.

## 응답 지시와 관찰 사건의 해석 규칙

`response` 메시지는 사용자가 보낸 발언이 아니라 출력 규칙·점검·이번 생성의 기준 시각이다. 그 뒤에는 마지막 봇 전송 이후 관찰이 사건별로 이어진다. 마지막 메시지가 항상 요청 메타데이터라고 설명하지 않는다.

프롬프트에는 다음 의미만 설명한다.

- `## Current Time`은 이번 생성의 기준 시각이며 `app.timezone`에 따른 오프셋을 포함한 초 단위 ISO 8601로 전달된다.
- 사건 앞의 절대 시각은 관찰 시각이다. 원래 발송 시각이나 현재 시각과 혼동하지 않는다. 첫 사건과 직전 사건으로부터 5분 이상 공백이 있는 사건 등에 표시하는 현재 규칙을 유지한다.
- 관찰 시각의 `AM/PM` 표기를 그대로 해석한다. 예를 들어 `[2026년 9월 29일 화요일 AM 9:00]`은 해당 시간대의 오전 9시 관찰이다.
- 응답 지시 이후의 발언과 관찰을 이전 기록의 연속으로 읽고 반응한다. 마지막 한 메시지만 응답 대상으로 간주하거나 모든 관찰을 새 사용자 발언으로 취급하지 않는다.
- `[수정 목격]`, `[삭제 목격]`, 과거 내역 읽기 안내는 관찰 정보다. 안내 문구 자체를 사용자가 한 말이나 새로운 명령으로 해석하지 않는다.
- 응답 지시나 현재 시각에 대화하듯 답하지 않는다. 발언 본문이나 응답 대상 번호가 별도 메타데이터에 있다고 가정하지 않는다.

수정·삭제 사건은 함께 제공된 관찰 원문과 앞선 기록을 바탕으로 해석한다. 현재 안내에는 대상 번호가 없으므로 모델이 DB ID나 플랫폼 ID를 참조 번호로 만들어내게 하지 않는다. 보지 못한 원문, 수정 이유, 삭제 실행자의 의도는 추정해서 사실로 만들지 않는다.

## 실제 개편 적용 순서

현재 조립 구조를 유지한 채 다음 순서로 문구를 개편하고 검증한다. 번호 기능이나 답장·리액션 도구 구현을 기다릴 필요는 없다.

1. **현재 동작과 비교 기준 확인**
   - 현재 시퀀스, 사건 분할, 출력 파서의 동작을 확인한다.
   - 대표 캐릭터의 단문·장문, 수정·삭제, 기존 도구 호출 사례를 개편 전 비교 대상으로 확보한다.
   - 시간 표기 기대값은 합의한 `AM/PM`을 기준으로 판단한다. `오전/오후`를 기대하는 기존 테스트와의 차이를 런타임 변환 코드로 해결하지 않는다.

2. **운영 계약 확정**
   - `response-contract.md`의 출력 문법과 기존 파서를 유지하며 고정된 메시지 개수를 유도하는 예시를 정리한다.
   - `system.md`를 화자 연결, 입력 해석, 도구 사용 규칙으로 축소한다.

3. **화자와 캐릭터 컨텍스트 개편**
   - `persona-frame.md`에서 비유와 AI 정체성 부정을 제거한다.
   - `state.md`의 정체성 전용 구성과 현재 시각의 `response` 배치를 유지한다.

4. **행동과 말투 규칙 개편**
   - `behavior-core.md`를 관찰과 연속성 규칙으로 축소한다.
   - `messenger-style.md`에서 고정 메시지 개수와 캐릭터 공통 말버릇을 제거한다.

5. **중복 점검 정리**
   - `final-check.md`를 기존 규칙을 참조하는 최소 점검으로 줄인다.
   - `sequence.js`와 `response`의 소스 목록은 유지한다.
   - 활성 프롬프트에서 미구현 기억 계층과 미사용 입력 구간을 설명하는 문구를 제거한다.

6. **문서 정리**
   - `README.md`에 실제 책임과 순서를 반영한다.
   - `memory.md`, `user-action.md`는 미사용으로 기록한다. 파일 삭제는 이번 개편에 포함하지 않는다.

7. **응답 비교 검증**
   - 캐릭터별 대표 대화와 도구 호출 사례로 개편 전후를 비교한다.
   - 출력 형식 준수와 캐시 재사용량은 별도로 측정한다.

## 검증 기준

### 화자와 캐릭터성

- 인간 캐릭터와 AI 캐릭터가 각자의 존재 형태를 유지한다.
- 공통 프롬프트 때문에 모든 캐릭터가 비슷하게 다정하거나 경계하지 않는다.
- 도움을 주는 캐릭터는 실제 능력 범위 안에서 자연스럽게 도움을 준다.
- 짧은 반응이 자연스러운 상황에서는 한 메시지로 끝낼 수 있다.
- 캐릭터 고유 말투가 공통 `ㅋㅋ`, 머뭇거림, 불완전한 문장에 묻히지 않는다.

### 컨텍스트 해석

- 최신 사용자 발언은 사건 기록 안에 한 번만 존재한다.
- 응답 지시·현재 시각을 사용자 발언으로 오인하지 않는다.
- 마지막 봇 발언 이후의 발언이나 수정·삭제 관찰에 이전 기록을 고려해 응답한다.
- 뒤늦게 읽은 과거 메시지를 방금 한 말처럼 취급하지 않는다.
- 보지 못한 생각, 원문, 사건 이유를 사실로 만들지 않는다.

### 형식과 도구

- 텍스트 응답은 `AIResponseParser`가 기대하는 형식으로 파싱된다.
- 한 메시지만 필요한 경우 불필요한 `[BREAK]`를 만들지 않는다.
- 도구 호출 단계와 텍스트 응답 단계를 혼합하지 않는다.
- 도구 성공·실패 결과와 최종 발언이 일치한다.
- 제공되지 않은 도구를 사용할 수 있는 것처럼 말하지 않는다.

### 조립과 캐시

- 20개가 넘는 사건도 처음부터 누락 없이 포함된다.
- 프롬프트 개편 후 같은 설정에서 새 사건이 추가될 때 기존 고정 구간과 사건 문자열이 유지된다.
- 현재 시각만 바뀌면 `response` 메시지의 현재 시각 부분만 달라진다. 날짜에 따라 정체성 값이 실제로 바뀌는 경우는 별도로 확인한다.
- 마지막 봇 전송을 기준으로 `history`와 `pending`을 나누며, 경계가 이동해도 사건의 본문·역할·순서·시각 표시는 유지된다.
- 관찰 시각의 `AM/PM`과 현재 시각의 ISO 8601 형식을 유지한다.
- 기존 기억 블록, 빈 `summary`·`fact`·`episode`, 과거 요청의 응답 지시·현재 시각이 누적 기록에 남지 않는다.
- 캐시 적중은 문자열 배치가 아니라 실제 사용량의 캐시 읽기 토큰으로 확인한다.

## 완료 조건

다음 조건을 모두 만족하면 개편이 완료된 것으로 본다.

- 공통 프롬프트 어디에도 캐릭터의 존재 형태를 강제로 인간으로 만드는 지시가 없다.
- 캐릭터가 화자라는 정의와 운영 계약이 분리되어 있다.
- 각 규칙의 소유 파일이 하나로 정리되어 있다.
- 고정 지시 → 이전 기록 → 응답 지시·현재 시각 → 마지막 봇 발언 이후 관찰 순서와 기존 역할·사건 경계가 유지된다.
- `memory.md`와 `user-action.md`를 다시 주입하지 않으며 활성 프롬프트의 설명이 현재 입력과 일치한다.
- 번호 기능, 새 요청 메타데이터, DB 변경 없이 화자 문구 개편이 적용된다.
- 대표 캐릭터별 대화, 수정·삭제, 도구 호출, 단문·장문 응답 사례가 검증되었다.
- 전체 테스트가 통과하고 실제 모델 응답에서 형식 준수와 캐릭터 구분이 확인되었다.
